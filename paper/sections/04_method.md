## 4. Метод

Предлагаемый слой устроен как каскад: единая нормализация кода (4.1) питает детерминированные детекторы по отпечаткам (4.2) и семантический энкодер (4.3), результаты которых объединяет гибридный детектор (4.4); порог решения задаётся конформной калибровкой (4.5); индекс эмбеддингов защищается ключевой проекцией, квантованием и шумом, стойкость которых проверяется тремя атаками (4.6); слой встраивается в шлюз как `pre_call`-проверка (4.7). Все детекторы реализуют единый интерфейс: `build(P)` строит индекс $I(P)$, `query(q)` возвращает тройку $(\mathrm{score}, \mathrm{best\_id}, \mathrm{details})$, что позволяет сравнивать методы одной процедурой калибровки и оценки. Гиперпараметры приведены по конфигурации стенда (`configs/default.yaml`).

### 4.1. Нормализация

Все методы работают не с текстом, а с потоком токенов, извлечённым из конкретного синтаксического дерева tree-sitter [TreeSitter]. Листовые узлы классифицируются на семь видов: идентификаторы (id), ключевые слова (kw; по спискам для каждого из шести языков), операторы (op), пунктуация (punct), числовые (num) и строковые (str) литералы, комментарии (comment; docstring Python относятся к комментариям). Над потоком $a_1,\dots,a_m$ определены три режима абстракции.

- **full**: id → `ID`, num → `NUM`, str → `STR`, комментарии удаляются. Поток инвариантен к T2–T4 по построению (клоны типа 2 [CloneTaxonomy]); используется в winnowing, MinHash, дедупликации и нормализованном хэше `sha`.
- **indexed**: идентификаторы заменяются на `ID_k` по порядку первого появления. Режим сохраняет схему потока данных (одинаковые позиции одного имени), оставаясь инвариантным к согласованному переименованию; на нём и на лексическом потоке строится BPE-словарь собственной малой модели (4.3).
- **lexical**: тексты токенов без комментариев; используется детектором M0 и словарём атаки A1.

Отдельно определена функция `strip_comments(q)`, возвращающая код без комментариев со схлопнутыми пустыми строками, — вход семантического энкодера. Разбор tree-sitter устойчив к ошибкам: листовые токены извлекаются и из поддеревьев `ERROR`, поэтому нормализация применима к неполным фрагментам (T7) и файловым окнам IDE, не совпадающим с границами функций. Все процедуры детерминированы и линейны по длине фрагмента.

### 4.2. Детерминированные детекторы M0–M2

**M0 exact.** Лексический поток без комментариев разбивается на окна по 5 строк; индекс — множество SHA-1 окон всех $s \in P$; $\mathrm{score}$ — доля окон запроса, найденных в индексе. Детектор служит нижней границей для T0–T2 и аналогом индексного сопоставления документов в DLP [SymantecIDM].

**M1 winnowing.** Для потока full-токенов $a_1,\dots,a_m$ образуются k-граммы $g_i = (a_i,\dots,a_{i+k-1})$, $i = 1,\dots,m-k+1$, и их ключевые хэши

$$h_i = \mathrm{trunc}_{64}\big(\mathrm{HMAC\text{-}SHA256}(K, g_i)\big), \qquad (1)$$

где $K$ — секретный ключ шлюза. По последовательности $h_1,\dots,h_{m-k+1}$ скользит окно из $w$ хэшей; в каждом окне выбирается минимум (при равенстве — самый правый), и множество выбранных хэшей образует отпечатки $F(q)$. Гарантия winnowing [Winnowing]: любая общая подстрока двух потоков длиной не менее

$$t = w + k - 1 \qquad (2)$$

токенов содержит ровно $w$ подряд идущих k-грамм, т. е. одно полное окно; выбор минимума зависит только от хэшей внутри окна и потому одинаков с обеих сторон, откуда следует хотя бы один общий отпечаток. Подстроки короче $k$ не обнаруживаются принципиально, подстроки длиной от $k$ до $t-1$ — лишь с некоторой вероятностью. В стенде $k = w = 25$, $t = 49$ токенов (порядка 5–8 строк): это разрешающая способность детерминированного слоя, с которой сопоставляются бины длины в разд. 6.2. Ожидаемая плотность отпечатков $2/(w+1)$ [Winnowing] определяет размер индекса.

Индекс $I_1(P)$ — отображение «хэш → компактный массив идентификаторов функций». Скор запроса

$$D_1(q) = \frac{|F(q)\cap F(P)|}{|F(q)|}, \qquad F(P) = \bigcup_{s\in P} F(s), \qquad (3)$$

$\mathrm{best\_id}$ — функция с наибольшим числом общих отпечатков; в `details` возвращается длина максимальной непрерывной цепочки общих отпечатков, используемая для объяснения вердикта (4.7).

Ключевое хэширование (1) отвечает модели нарушителя Н4: без $K$ хэш ни одной k-граммы невычислим, поэтому утёкший индекс не позволяет ни проверить гипотезу о содержимом $P$, ни перечислить его перебором по словарю типовых k-грамм, что возможно для бесключевых хэшей. Усечение до 64 бит даёт вероятность хотя бы одной случайной коллизии в индексе из $|F(P)|$ отпечатков порядка $|F(P)|^2/2^{65}$, пренебрежимо малую при $|F(P)| \le 10^8$.

**Фильтр общности.** Отпечатки, встречающиеся более чем в `common_df` = 50 функциях public_train либо более чем в 5 % файлов protected, исключаются из $F(P)$ и не учитываются в $F(q)$ (при пустом знаменателе в (3) скор полагается равным 0). Фильтр меняет смысл гарантии (2): общая подстрока длиной $\ge t$ теперь обнаруживается тогда и только тогда, когда хотя бы один из выбранных в ней отпечатков не принадлежит множеству общих $C$. Подстрока, все отпечатки которой лежат в $C$, состоит из k-грамм, типичных для открытого кода (прологи импорта, шаблонная обработка ошибок, геттеры, лицензионные заголовки), и её наличие в запросе одинаково совместимо с происхождением как из $P$, так и извне; такая подстрока не является свидетельством членства, и её «необнаружение» — не потеря полноты, а снижение ложных срабатываний. В этом отличие задачи членства от задачи поиска плагиата, где засчитывается любое совпадение. Ценой является отказ от безусловной гарантии: доля отпечатков protected, удалённых фильтром, отчитывается в ⟨T1: доля отпечатков protected, удалённых фильтром общности⟩, а влияние фильтра на TPR и FPR — в ⟨T4: winnowing с фильтром и без⟩.

**M2 MinHash.** Шинглы из 5 full-токенов образуют множество; по нему вычисляется MinHash со 128 перестановками [datasketch] (стандартная ошибка оценки коэффициента Жаккара $\approx 1/\sqrt{128} \approx 0{,}09$), LSH отбирает кандидатов, для которых считается точный коэффициент Жаккара; $D_2(q)$ — его максимум. В отличие от зависящего от порядка winnowing, мешок шинглов терпим к перестановке операторов (T6) и частично к мёртвому коду (T5), подобно мешку токенов SourcererCC [SourcererCC]; слабость — частичное извлечение (T7), при котором коэффициент Жаккара короткого окна и полной функции мал по построению.

### 4.3. Семантический энкодер M3

**Архитектура и вход.** Базовая модель — UniXcoder-base [UniXcoder] (трансформер-энкодер, 12 слоёв, размерность $d = 768$); альтернативы через конфигурацию — `codet5p-110m-embedding` [CodeT5+] и `codesage-small`. Эмбеддинг

$$e = f(q) = \frac{\mathrm{mean}_j\,\mathrm{Enc}\big(\mathrm{strip\_comments}(q)\big)_j}{\big\lVert \mathrm{mean}_j\,\mathrm{Enc}(\cdot)_j \big\rVert_2}, \qquad (4)$$

то есть усреднение по позициям (mean pooling) и L2-нормализация; вход — не более 512 подтокенов (более длинные функции усекаются, полноту для них дополняют файловые окна). Благодаря нормализации косинус равен скалярному произведению, и

$$D_3(q) = \max_{i \in \mathrm{top}k(e)} \langle e, e_i\rangle, \qquad e_i = f(s_i), \quad k = 20. \qquad (5)$$

**Контрастивное дообучение.** Модель без дообучения (zero-shot) — базовая линия. Дообучение выполняется на public_train: якорь $a_i$ — функция, позитив $p_i = t(a_i)$ — её случайное программное преобразование $t \sim \mathrm{Unif}(T)$ (LLM-преобразования добавляются, если сгенерированы). Негативы для $a_i$ — остальные позитивы батча ($B = 128$) и множество $H_i$ из двух трудных негативов: функций того же файла (при нехватке — того же репозитория). Потеря — симметричный InfoNCE [InfoNCE; SimCSE] с температурой $\kappa = 0{,}05$ (обозначение $\tau$ зарезервировано за порогом):

$$\ell(a_i\!\to\!p) = -\log\frac{\exp(\langle e_{a_i}, e_{p_i}\rangle/\kappa)}{\sum_{j=1}^{B}\exp(\langle e_{a_i}, e_{p_j}\rangle/\kappa)+\sum_{h\in H_i}\exp(\langle e_{a_i}, e_h\rangle/\kappa)}, \qquad (6)$$

$$\mathcal{L} = \frac{1}{2B}\sum_{i=1}^{B}\big[\ell(a_i\!\to\!p) + \ell(p_i\!\to\!a)\big]. \qquad (7)$$

Оптимизатор AdamW, скорость обучения $2\cdot10^{-5}$, разогрев 5 %, 2 эпохи, bf16, контрольные точки градиента; валидация по recall@1 на парах public_calib, сохраняется лучшая эпоха. Трудные негативы из того же файла — ключевой элемент: негативы из других предметных областей разделяются тривиально, тогда как соседние функции делят словарь, API и стиль — именно то, что моделирует набор hard_neg; энкодер вынужден кодировать структуру самой функции, а не стиль репозитория. Поскольку негативы батча сами являются преобразованными позитивами других якорей, артефакты преобразований не могут стать признаком класса.

Защищённый код $P$ в обучении не участвует: модель является общей для всех заказчиков и не требует переобучения при изменении $P$. Абляция `adapt_on_protected` (дообучение с участием $P$, заказчик-специфичная адаптация) оценивается отдельно ⟨T4: TPR semantic при adapt_on_protected⟩ наряду с zero-shot ⟨T4: TPR semantic zero-shot⟩.

**Собственная малая модель.** Вариант `own_small_model` — трансформер из 6 слоёв (размерность 384, 6 голов внимания, BPE-словарь 32 000 над indexed- и lexical-потоками), обучаемый с нуля той же потерей (6)–(7). Он не наследует весов и лицензионных ограничений сторонних моделей, что важно для on-prem развёртывания и требований к доверенным технологиям ИИ [FSTEC2026]; его цена по полноте — ⟨T4: TPR own_small_model⟩.

**Поиск ближайших соседей.** Индекс $I_3(P)$ — матрица $E \in \mathbb{R}^{N\times d}$ в float16 ($2Nd$ байт); поиск top-$k$ — FAISS `IndexFlatIP` или HNSW [FAISS]; при $N \le 2\cdot10^5$ на CPU — точное матричное произведение numpy.

### 4.4. Гибридный детектор M4

Семантический поиск обеспечивает полноту при преобразованиях, разрушающих k-граммы, но его скор — непрерывная мера сходства, не отличающая «ту же функцию с переименованными переменными» от «похожей функции того же назначения». Отпечатки, напротив, точны, но хрупки. Гибрид использует ANN как генератор кандидатов, а лексические меры — как подтверждение, подобно HybridSourceTracker [HST], переранжирующему векторный поиск отпечатками winnowing; отличия — обучаемый комбинатор с несколькими признаками и конформный порог. Для каждого кандидата $c$ из top-20 по (5) вычисляется вектор признаков

$$x(q,c) = \big[\langle e_q, e_c\rangle,\ \mathrm{ovl}_w(q,c),\ \mathrm{lcs}(q,c)/m_q,\ m_q\big], \qquad (8)$$

где $\mathrm{ovl}_w$ — доля отпечатков $q$, присутствующих у $c$ (попарно, без фильтра общности), $\mathrm{lcs}$ — длина наибольшей общей подпоследовательности full-токенов, нормированная на длину запроса $m_q$ (мера порядка, проходящая «сквозь» вставленный мёртвый код, в отличие от k-грамм), $m_q$ — длина запроса в токенах, позволяющая комбинатору по-разному доверять косинусу для коротких и длинных фрагментов. Скор

$$D_4(q) = \max_{c\in\mathrm{top}k}\ \sigma\big(\beta_0 + \beta^{\top}x(q,c)\big). \qquad (9)$$

Логистический комбинатор обучается на public_train: индекс строится по public_train, члены — пары $(t(a), a)$, не-члены — пары $(t(a), c)$ для кандидатов $c \ne a$ из top-$k$; $P$ не используется. Абляция без обучения — правило двух порогов: кандидат считается подтверждённым отпечатками при $\mathrm{ovl}_w(q,c) \ge \theta_w$, и

$$D_{4}^{(2)}(q) = \max_{c\in\mathrm{top}k}\ \frac{\langle e_q,e_c\rangle + \lambda\,\mathbb{1}[\mathrm{ovl}_w(q,c)\ge\theta_w]}{1+\lambda}, \qquad (10)$$

где $\theta_w$ и $\lambda$ задаются заранее без обучения, а единственный калибруемый порог — $\tau_\alpha$. Вклад обучаемого комбинатора и каждого признака — ⟨T4: абляция признаков гибрида⟩, ⟨F5⟩.

### 4.5. Конформная калибровка порога

Для каждого детектора $D$ и уровня $\alpha \in \{10^{-2}, 10^{-3}\}$ порог вычисляется методом split conformal для нулевого класса [Conformal; GentleIntro]. Пусть $S = \{s_1,\dots,s_n\}$ — скоры негативов калибровки (public_calib с той же матрицей преобразований, что и у членов), $s_{(1)}\le\dots\le s_{(n)}$ — их порядковые статистики. Тогда

$$\tau_\alpha = s_{(\lceil (n+1)(1-\alpha)\rceil)}, \qquad (11)$$

где при $\lceil (n+1)(1-\alpha)\rceil > n$ полагается $\tau_\alpha = +\infty$; содержательный порог существует при $n \ge \lceil 1/\alpha\rceil - 1$ (999 негативов для $\alpha = 10^{-3}$; в стенде $n$ = ⟨T1: число запросов public_calib⟩).

*Утверждение.* Если скор нового не-члена $s_{\mathrm{new}}$ обменяем с $s_1,\dots,s_n$, то $\Pr[s_{\mathrm{new}} \ge \tau_\alpha] \le \alpha$; при непрерывном распределении скоров также $\Pr[s_{\mathrm{new}} \ge \tau_\alpha] \ge \alpha - 1/(n+1)$. Доказательство: в силу обменяемости ранг $r$ величины $s_{\mathrm{new}}$ среди $n+1$ скоров распределён равномерно на $\{1,\dots,n+1\}$; событие $s_{\mathrm{new}} \ge s_{(j)}$ при $j = \lceil (n+1)(1-\alpha)\rceil$ требует $r \ge j+1$, откуда $\Pr \le (n+1-j)/(n+1) \le \alpha$. Нижняя оценка показывает, что порог не переконсервативен.

Границы применимости. (i) Гарантия маргинальна — усреднена по случайности калибровочной выборки и по смеси запросов; внутри подгруппы (язык, преобразование, бин длины) FPR может превышать $\alpha$, поэтому FPR отчитывается и по подгруппам ⟨T3: FPR по наборам и подгруппам⟩. (ii) Строгая обменяемость выполняется при одном запросе на функцию-источник; при полной матрице «функция × преобразование» калибровочные скоры кластеризованы, граница выполняется приближённо и проверяется эмпирически с бутстрэпом по исходным функциям. (iii) Главное ограничение — сдвиг распределения: трудные негативы из предметной области $P$ не обменяемы с public_calib, их скоры стохастически больше, и эмпирический FPR на hard_neg может превышать заявленный $\alpha$; величина превышения с интервалами Клоппера–Пирсона [ClopperPearson] — предмет RQ2 ⟨T3: FPR на hard_neg при α = 1 %⟩, ⟨F4⟩. (iv) Доменная калибровка: часть репозиториев hard_neg добавляется к калибровочным негативам, остальные остаются в тесте; это восстанавливает обменяемость относительно доменной популяции ценой более высокого порога и, следовательно, меньшей полноты ⟨T3: TPR при доменной калибровке⟩. Для сравнения приводится «оракульный» порог, выбранный по public_test. Та же процедура (11) применяется под каждой защитой индекса (4.6), так что граница FPR сохраняется, а измеряется только потеря TPR. Совместная калибровка нескольких порогов (например, $\theta_w$ и $\tau$ в (10)) возможна методами Learn then Test и конформного контроля риска [LTT; CRC] и оставлена за рамками работы.

### 4.6. Приватность индекса эмбеддингов

Индекс $I_3(P)$ хранит $E = [e_1,\dots,e_N]$ — непрерывное представление $P$, пригодное для инверсии [vec2text; SongRaghunathan]. Рассматриваются три защиты и три атаки.

**Ключевая ортогональная проекция.** Из ключа детерминированно порождается гауссова матрица $G \in \mathbb{R}^{d\times d}$, QR-разложение даёт ортогональную $Q$ ($Q^{\top}Q = I$); в индексе хранятся $e'_i = Qe_i$, запрос проецируется той же матрицей: $e'_q = Qf(q)$. Поскольку

$$\langle e'_q, e'_i\rangle = e_q^{\top}Q^{\top}Qe_i = \langle e_q, e_i\rangle, \qquad (12)$$

косинусы, top-$k$, скоры (5), (9) и калиброванные пороги не меняются — защита бесплатна по полноте. Модели инверсии, которые нарушитель обучает на собственном экземпляре энкодера, — функции координат; при неизвестном повороте базиса их вход перестаёт соответствовать обучающему распределению, и без оценки $Q$ инверсия вырождается. Проекция не скрывает геометрию: попарные расстояния между векторами индекса сохраняются (утекает структура кластеров и дубликатов $P$), а при утечке пар «код — вектор» матрица $Q$ восстановима (атака A2).

**Квантование и шум.** Квантование до int8, int4 и бинарного (знакового) представления сокращает память в 2, 4 и 16 раз относительно float16 и уничтожает младшие разряды координат. Шум $\tilde e_i = Qe_i + \xi_i$, $\xi_i \sim \mathcal{N}(0, \sigma^2 I_d)$, $\sigma \in \{0{,}05;\ 0{,}1;\ 0{,}2\}$, добавляется только к хранимым векторам; ожидаемый косинус между чистым и зашумлённым вектором $\approx 1/\sqrt{1+\sigma^2 d}$, что при $d = 768$ делает $\sigma$ явным регулятором компромисса «утечка — полнота». Адаптивные к размерностям схемы шума [TextCrafter; SPARSE] совместимы с конструкцией, но не исследуются.

**Атаки.** A1 — инверсия «мешок токенов»: MLP $g_\phi:\mathbb{R}^d\to[0,1]^V$ предсказывает по вектору наличие каждого из $V = 20\,000$ наиболее частых идентификаторов public_train; обучение бинарной кросс-энтропией на парах $(f(a), \mathrm{bow}(a))$, $a \in$ public_train; оценка на $P$: F1 по токенам и доля восстановленных редких идентификаторов ($\mathrm{df}\le 3$ в public) — именно они несут предметные имена [SongRaghunathan]. A1 без защит — верхняя граница утечки. A2 — выравнивание по $n$ утёкшим парам $(s_j, e'_j)$, $n \in \{100, 1000, 10\,000\}$ [ALGEN]: нарушитель вычисляет $e_j = f(s_j)$ и решает задачу ортогонального Прокруста

$$\hat Q = \arg\min_{Q^{\top}Q = I}\lVert E' - EQ^{\top}\rVert_F = UV^{\top}, \qquad U\Sigma V^{\top} = \mathrm{SVD}(E'^{\top}E), \qquad (13)$$

после чего применяет A1 к $\hat Q^{\top}e'$. Без шума и квантования $n \ge d$ линейно независимых пар восстанавливают $Q$ точно; при $n < d$ оценка корректна лишь на подпространстве, натянутом на утёкшие пары, а квантование и шум ухудшают $\hat Q$ — сетка $n$ покрывает оба режима для $d = 768$, давая кривую утечки ⟨F6⟩. A3 — генеративная инверсия: 6-слойный декодер, обусловленный на $e'$, обучается восстанавливать `strip_comments(a)`; метрики — BLEU и точное совпадение идентификаторов; одношаговая схема без итеративной коррекции [vec2text] даёт нижнюю оценку генеративной утечки. Полезность каждой конфигурации защиты — TPR@FPR = 1 % детекторов M3/M4 при той же калибровке ⟨T6: TPR@FPR=1 % и утечка A1/A2 по защитам⟩, ⟨F6⟩.

### 4.7. Схема развёртывания в файрволе

Слой встраивается в прокси перед моделью как `pre_call`-guardrail (интерфейс LiteLLM [LiteLLM]) с действиями `BLOCKED`, `GUARDRAIL_INTERVENED` (маскирование блока кода по аналогии с заменой чувствительных сущностей в HaS и PAPILLON [HaS; PAPILLON]) и `NONE`:

```
procedure PRE_CALL(prompt):
    action ← NONE
    for q in extract_code_blocks(prompt):
        lang ← detect_lang(q);  toks ← tokenize(q, lang)
        r1 ← M1.query(abstract(toks, "full"))             # поиск по словарю, O(|F(q)|)
        if r1.score ≥ τ_α^{(1)}: return BLOCKED(explain(r1.best_id))
        e' ← Q · f(strip_comments(q))                       # энкодер — доминирующая стоимость
        C ← ANN.topk(e', 20);  r4 ← M4.rerank(q, C)         # признаки (8), скор (9)
        if r4.score ≥ τ_α^{(4)}:  return BLOCKED(explain(r4.best_id))
        if r4.score ≥ τ_{α'}^{(4)}: action ← GUARDRAIL_INTERVENED   # α' > α: маскирование блока
    return action
```

Пороги $\tau^{(1)}_\alpha$ и $\tau^{(4)}_\alpha$ калибруются по (11) независимо для каждой ступени. Бюджет латентности (50 мс для чата, 20 мс для IDE) распределяется так: нормализация и поиск отпечатков — операции со словарём, микросекунды; доминируют инференс энкодера на CPU и ANN, стоимость которого при точном поиске линейна по $N$ ⟨T5: латентность p50/p95 M3/M4 на CPU, 1 и 4 потока⟩, ⟨F7⟩. Для сценария IDE короткие окна дают короткие последовательности, конкурентные запросы батчируются, при $N \sim 10^6$ используется HNSW или GPU. Память: отпечатки — около $2m/(w+1)$ 64-битных хэшей на функцию длиной $m$ токенов плюс идентификаторы; эмбеддинги — $2Nd$ байт в float16 или $Nd$ байт при int8 ⟨T5: память индексов M1–M4⟩.

Объяснение вердикта строится по `best_id` формата `repo/path:start-end` и по `details` (число общих отпечатков, длина непрерывного совпадения, косинус): полная форма направляется в журнал SOC и офицеру безопасности, пользователю — сокращённая («фрагмент совпадает с функцией защищённого репозитория»). Детализированная обратная связь пользователю намеренно не выдаётся: для нарушителя Н3 она служила бы оракулом для итеративного обхода; дополнительно ограничивается частота околопороговых запросов. Ключ $K$ и затравка матрицы $Q$ хранятся в секретном хранилище шлюза отдельно от индекса; ротация $K$ требует переиндексации $P$ (офлайн, линейно по объёму). Обновление $P$ инкрементально (вставка в словарь, `add` в FAISS); поскольку распределение скоров негативов зависит от размера $P$, после существенного роста индекса калибровочный набор пересчитывается по (11) без повторного сбора данных.
