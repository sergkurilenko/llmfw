## 2. Модель угроз и постановка задачи

### 2.1. Определения

Пусть P = {s_1, …, s_N} — защищённая кодовая база: множество фрагментов исходного кода (функций, а для сценария IDE — также файловых окон фиксированной длины), извлечённых из закрытых репозиториев организации; рассматриваемый диапазон N ≈ 10^5–10^6 (в стенде — ⟨T1: число функций и окон protected⟩). По P офлайн строится индекс I(P), который развёртывается на шлюзе между пользователями и большой языковой моделью; сама база на шлюз не передаётся. Шлюз реализует требование не передавать информацию ограниченного доступа разработчику модели [FSTEC2026]. Запрос q — фрагмент кода, выделенный из промпта предшествующими слоями файрвола (разбор сообщения, извлечение блоков кода, определение языка).

Классом преобразований T назовём множество отображений t: s ↦ t(s), каждое из которых переводит фрагмент кода в фрагмент кода на том же или ином языке программирования и может быть рандомизированным (случайные имена, случайные позиции вставок). Фрагмент q называется членом P относительно T (обозначение q ∈_T P), если существуют s ∈ P и t ∈ T такие, что q = t(s); фрагмент, полученный из кода вне P, — не-членом. При T = {identity} определение сводится к точному совпадению; при расширении T задача приближается к обнаружению клонов типов 1–4 по классификации [CloneTaxonomy], но с существенным отличием: одна сторона сравнения (P) фиксирована и закрыта, а решение принимается в реальном времени по одному запросу без доступа к его происхождению.

Детектор D: q ↦ score ∈ [0, 1] вычисляет меру принадлежности; решение принимается правилом D_τ(q) = 1[D(q) ≥ τ] с порогом τ. Полнота по классу t ∈ T определяется как TPR_t(τ) = Pr[D(t(s)) ≥ τ | s ∈ P], уровень ложных срабатываний — как FPR(τ) = Pr[D(q) ≥ τ | q ∉_T P]; обе величины рассматриваются также условно по языку программирования и по длине фрагмента n_tokens(q).

### 2.2. Требования к детектору

(a) Полнота. Детектор должен сохранять высокую TPR_t при всех t ∈ T, включая преобразования, разрушающие k-граммы (переименование, вставка мёртвого кода, перефраз), и при коротких фрагментах — от нескольких строк, вырезанных из тела функции, до функции целиком. Полнота отчитывается по классам T и по бинам длины (0–32, 32–64, 64–128, 128–256, более 256 токенов).

(b) Ограниченный FPR с конечновыборочной гарантией. Для заданного уровня α ∈ {10^−2, 10^−3} порог τ_α должен обеспечивать FPR ≤ α не асимптотически и не «в среднем по обучению», а в виде гарантии, выполняющейся при конечной калибровочной выборке негативов без предположений о форме распределения скоров; такую гарантию даёт конформная калибровка [Conformal; GentleIntro] (разд. 4). Поскольку гарантия опирается на обменяемость новых негативов с калибровочными, её соблюдение при сдвиге распределения — на коде той же предметной области, что и P (трудные негативы), — является отдельным предметом проверки с доверительными интервалами Клоппера–Пирсона [ClopperPearson].

(c) Латентность. Шлюз обрабатывает запрос синхронно, поэтому бюджет слоя на CPU ограничен 50 мс для чата и 20 мс для автодополнения в IDE при индексе из 10^5–10^6 функций; память индекса должна допускать размещение на одном узле шлюза.

(d) Приватность индекса. I(P) содержит производную информацию о коде, составляющем коммерческую тайну [98-ФЗ], и размещается на шлюзе, который сам может быть скомпрометирован. Требуется, чтобы без ключа из I(P) нельзя было восстановить P (лексику, идентификаторы, структуру функций) сверх заданной границы, а при утечке n пар «код — вектор» объём восстанавливаемой информации рос контролируемо; при этом защитные преобразования индекса не должны существенно снижать полноту (a).

### 2.3. Нарушители

Принимается допущение Керкгоффса: нарушителю известны алгоритмы детектора (энкодер, параметры winnowing k и w, схема калибровки), но неизвестны секретный ключ HMAC отпечатков и ключевая ортогональная матрица Q проекции эмбеддингов. Рассматриваются четыре модели нарушителя, различающиеся умыслом, объёмом трафика и доступом.

Н1. Небрежный сотрудник. Вставляет в чат функцию или её часть без намерения обойти контроль; преобразования — побочный результат копирования и минимальной адаптации: переформатирование, удаление комментариев, подстановка своих литералов, частичное извлечение. Именно этот канал преобладает в отраслевой статистике: исходный код составляет 42 % нарушений политик данных в GenAI-трафике [Netskope2026] и 18,7 % чувствительных вводов [Cyberhaven2026]; известный пример — три случая передачи кода Samsung в ChatGPT за 20 дней [Samsung2023].

Н2. IDE-ассистент. Автоматически отправляет контекст редактируемого файла: короткие окна (единицы–десятки строк) с границами, не совпадающими с границами функций, с высокой частотой запросов. Умысла нет, но объём и фрагментарность исключают ручной разбор, а бюджет латентности минимален. Для этого сценария P дополняется файловыми окнами, а T — частичным извлечением с L ∈ {3, 5, 10, 20, 40} строк.

Н3. Инсайдер с умыслом. Знает о детекторе и целенаправленно преобразует код так, чтобы сохранить его полезность для модели, но разрушить признаки сопоставления: согласованное переименование идентификаторов и замена литералов (разрушают лексические k-граммы); вставка мёртвого кода — автоматизированная атака на MOSS, показавшая, что отпечатки winnowing обходятся без изменения поведения программы [Mossad]; перестановка независимых операторов; комбинация перечисленного; наконец, перефраз и перевод на другой язык программирования с помощью общедоступной LLM. Ограничение атакующего — сохранение синтаксической корректности и смысла фрагмента, иначе ответ модели теряет ценность. Доступа к шлюзу и ключам нарушитель не имеет.

Н4. Компрометация шлюза. Нарушитель получает копию I(P): индекс отпечатков (HMAC-хэши k-грамм → идентификаторы функций) и индекс эмбеддингов (векторы e'_i = Q·f(s_i), возможно квантованные и зашумлённые). Без ключа HMAC хэши k-грамм невоспроизводимы и не допускают перебора по словарю; даже при утечке ключа индекс отпечатков позволяет лишь проверять известные кандидаты, но не перечислять P. Поэтому основной риск сосредоточен в эмбеддингах, несущих непрерывное представление кода. Рассматриваются два уровня знаний: (i) доступ к индексу без ключа и без пар «код — вектор» — нарушитель обучает модели инверсии только на собственных данных и собственном экземпляре энкодера; (ii) доступ с n утёкшими парами (s_j, e'_j), n ∈ {100, 1000, 10000} (например, из журналов отладки), по которым оценивается выравнивание Q̂ между пространствами. Реалистичность угрозы подтверждена для текстовых эмбеддингов: восстановление 92 % входов длиной 32 токена по вектору [vec2text], выравнивание между моделями по ~10^3 парам [ALGEN], извлечение атрибутов и мешка слов из вектора [SongRaghunathan].

### 2.4. Вне рамок

Не рассматриваются: (1) пересказ алгоритма словами на естественном языке без кода — задача семантической классификации текста, а не членства кода; (2) сессионное дробление — передача функции мелкими частями в разных запросах или сессиях, объединение которых требует отслеживания состояния пользователя и относится к другому слою файрвола; (3) провенанс в обратном направлении — проверка, не воспроизводит ли ответ модели код из P [HST]; (4) кодирование транспортного уровня (архивы, base64), снимаемое слоем нормализации до детектора. Поведенческая эквивалентность LLM-преобразований исходному коду не проверяется: достаточным считается синтаксически корректный результат (разд. 5).

### 2.5. Таксономия преобразований

Таблица 1 сводит классы преобразований T, используемые для построения запросов и оценки полноты. Для каждого указаны тип клона по [CloneTaxonomy], который он моделирует, и нарушитель, для которого он характерен. Преобразования T0–T8 реализованы программно на синтаксических деревьях tree-sitter [TreeSitter] и детерминированы по seed; T9 порождается LLM (Qwen2.5-Coder-7B-Instruct) и принимается только при синтаксически корректном результате. Влияние каждого класса на полноту отпечатков и семантического слоя оценивается в разд. 6.1 (⟨T2⟩, ⟨F1⟩), LLM-преобразований — в разд. 6.7 (⟨T7⟩).
