# Статья «Семантическое членство кода» — как устроена рукопись и как её довести до подачи

Каталог `paper/` содержит рукопись статьи для журнала ВАК (специальность 2.3.6 «Методы и системы защиты информации»), написанную по дизайну исследования `docs/semantic_membership/DESIGN.md` и прошедшую один раунд рецензирования (правки внесены). Числовых результатов в рукописи ещё нет: все места, где должно стоять число, помечены плейсхолдерами `⟨…⟩`, которые заполняются после прогона стенда `experiments/semantic_membership/` на GPU-машине.

## 3. Плейсхолдеры: виды и как их заполнять

Все плейсхолдеры имеют вид `⟨…⟩` (U+27E8/U+27E9; `grep -o '⟨[^⟩]*⟩'` находит ровно их). Виды:

1. `⟨Tn: описание⟩` — одно число из `results/tables/Tn_*.md` (T1 — из `results/summary.json: data_stats`). Пример: `⟨T2: TPR M1/insert_deadcode⟩` — ячейка «M1 winnowing» × «t_5 insert_deadcode» таблицы T2. Внутри плейсхолдеров методы названы кодовыми именами (`M1`/`winnowing`, `M3`/`semantic` — дообученный, если не сказано zero-shot, `M4`/`hybrid`), преобразования — именами из `configs/default.yaml: transforms`; `CPU-1` / `CPU-все` — один поток / все потоки процессора стенда (код измеряет именно эти две конфигурации, `embed.measure_latency`); `GPU-1` / `GPU-32` — размер пакета.
2. `⟨Fn: описание⟩` — число из данных рисунка (`09_report.py` должен сохранять рядом с `Fn_*.png` файл с точками).
3. `⟨summary: tpr_windows overall/M1⟩` — из `results/summary.json: methods.<m>.tpr_windows` (набор protected_windows); `⟨index_stats: winnowing n_common_protected / n_fps_total⟩` — из `results/index_stats.json` (meta индекса winnowing).
4. Голые `⟨Tn⟩` в ячейках таблиц 2–7 — вставить значения из `results/tables/Tn_*.md`. **Таблицы рукописи — проекции таблиц стенда**, а не копии: стенд выводит надмножество столбцов (T2 — дополнительно строку «оракульный порог»; T3 — столбцы доменной калибровки и «FPR public_test > α»; T5 — «Прогон eval» и «Построение индекса»; T6 — полностью, в рукописи только рис. 7; T7 — строки по целевым языкам и FPR всех методов). Соответствие столбцов — по заголовкам; при расхождении править `smcode/eval/tables.py`, а не рукопись.
5. Метки `(Tn)` / `(Fn)` в конце подписей таблиц и рисунков — соответствие «номер в рукописи ↔ файл стенда»; перед подачей удалить.
6. Прочие: `⟨GPU⟩`, `⟨CPU⟩` (модель ускорителя и процессора, число потоков), `⟨URL репозитория⟩`, `⟨источник финансирования…⟩`, `⟨заполняет редакция⟩`.

Порядок заполнения: `⟨T1⟩` (N функций и окон protected — разд. 3.1, аннотация, введение, заключение; число функций и запросов public_calib — разд. 4.5, 6.3) → таблицы 3–7 → текстовые плейсхолдеры разд. 6 → разд. 1, 7, 8 и аннотации (повторяют числа разд. 6, сверять) → `⟨Fn⟩`. Шаблонные фразы разд. 6 написаны направление-нейтрально («разность … равна ⟨…⟩», «отношение FPR/α равно ⟨…⟩»); после заполнения проверить согласование падежей и знаков, но переписывать выводы не потребуется. Причинные интерпретации вынесены в разд. 7 и сформулированы как интерпретации. Проверка: `grep -c '⟨' paper/semantic_membership_ru.md` должно дать 0.

## 6. Объём и выбор журнала

После правок рукопись занимает ≈ 2,1 а.л. с пробелами (≈ 85 тыс. знаков; из них список литературы ≈ 0,25 а.л., основной текст с таблицами и формулами ≈ 1,9 а.л.) против ≈ 2,6 а.л. до рецензирования; разд. 2 сокращён до ~0,15 а.л., дублирование гиперпараметров (разд. 4 ↔ 5.2) и схемы развёртывания (разд. 4.7 ↔ 7.1) убрано, псевдокод PRE_CALL исключён (ниже), разд. 6 содержит только сравнения, табл. T6 и строки T7 по языкам оставлены в репозитории, разд. 7.3–7.4 слиты с 7.1–7.2. Дальнейшее сжатие упирается в содержание, которого требовали другие замечания (формулы (1)–(12), таблицы 1–7, модель нарушителя, цель/задачи/новизна). Для журнала с лимитом 1,5 а.л. («Труды ИСП РАН» и аналогичные) нужно снять ещё ≈ 0,6 а.л.: блок «по языкам» табл. 3 → одна строка «разброс по языкам» (−0,05), табл. 5 (абляции) → репозиторий с текстовым резюме (−0,05), разд. 2 → один абзац (−0,1), разд. 3.3 и 4.6 → сжать вдвое (−0,15), список литературы → 30 позиций (−0,08), разд. 6 — только итоговые дельты (−0,15). Для лимита 1 а.л. (40 тыс. знаков) рукопись следует разделить на две статьи: (А) «детектор + конформная калибровка» — RQ1–RQ4 (убрать разд. 4.6, 6.6, рис. 7, пункт 5 результатов и новизны, ~10 позиций литературы по инверсии эмбеддингов; ≈ 1,8 а.л., далее сжимать по списку выше) и (Б) «приватность индекса эмбеддингов кода» — RQ5 с кратким изложением детектора.

Псевдокод pre_call-ограждения (исключён из рукописи, разд. 4.7 описывает его словами):

```
procedure PRE_CALL(prompt):
    action ← NONE
    for q in extract_code_blocks(prompt):
        toks ← tokenize(q, detect_lang(q))
        r1 ← M1.query(abstract(toks, "full"))                 # поиск по словарю отпечатков
        e′ ← Q · f(strip_comments(q))                          # энкодер — доминирующая стоимость
        r4 ← M4.rerank(q, ANN.top_R(e′))                       # признаки (7), оценка (8); всегда вычисляется
        if r1.score > τ^(1)_{α/2} or r4.score > τ^(4)_{α/2}: return BLOCKED(explain(best_id))
        if r4.score > τ^(4)_{α′}: action ← GUARDRAIL_INTERVENED   # α′ > α: маскирование блока
    return action
```
