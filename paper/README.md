# Статья «Семантическое членство кода» — как устроена рукопись и как её довести до подачи

Каталог `paper/` содержит рукопись статьи для журнала ВАК (специальность 2.3.6 «Методы и системы защиты информации»), написанную по дизайну исследования `docs/semantic_membership/DESIGN.md` и прошедшую один раунд рецензирования (правки внесены). Числовых результатов в рукописи ещё нет: все места, где должно стоять число, помечены плейсхолдерами `⟨…⟩`, которые заполняются после прогона стенда `experiments/semantic_membership/` на GPU-машине.

## 1. Файлы

| Путь | Что это |
|---|---|
| `paper/semantic_membership_ru.md` | Единая рукопись (Markdown): титул, аннотации RU/EN, разделы 1–8, благодарности, конфликт интересов, список литературы. Рабочий файл; правки вносить в него. |
| `paper/sections/00_abstract.md … 07_discussion.md` | Черновики разделов первой версии (до рецензирования). Не являются источником истины; хранятся для истории. |
| `paper/figures/` | Сюда `smcode.eval.plots` (скрипт `09_report.py`) кладёт рисунки `F1_…png … F7_…png`. Пока пусто. |

## 3. Плейсхолдеры: виды и как их заполнять

Все плейсхолдеры имеют вид `⟨…⟩` (U+27E8/U+27E9; `grep -o '⟨[^⟩]*⟩'` находит ровно их). Виды:

1. `⟨Tn: описание⟩` — одно число из `results/tables/Tn_*.md` (T1 — из `results/summary.json: data_stats`). Пример: `⟨T2: TPR M1/insert_deadcode⟩` — ячейка «M1 winnowing» × «t_5 insert_deadcode» таблицы T2. Внутри плейсхолдеров методы названы кодовыми именами (`M1`/`winnowing`, `M3`/`semantic` — дообученный, если не сказано zero-shot, `M4`/`hybrid`), преобразования — именами из `configs/default.yaml: transforms`; `CPU-1` / `CPU-4` — 1 и 4 потока процессора (`eval.latency_threads: [1, 4]`, `embed.measure_latency`; в T5 столбцы «CPU, 1 поток» и «CPU, 4 потоков» строки «инференс энкодера»); `GPU-1` / `GPU-32` — размер пакета. «Сквозная p95 M4, CPU-1» — столбец «Сквозная латентность запроса … (CPU-1, оценка)» T5 (= `summary.latency_ms.end_to_end`: энкодер CPU-1 батч 1 + бенчмарк батча 1 `--bench`); «бенчмарк пакета 1, p95, M3/M4» — строка «— бенчмарк батч 1» под методом; «записей M4» — столбец «Записей». `⟨T3 (окна): …⟩` — блок «Сценарий IDE» файла `T3_fpr_guarantee.md` (столбцы τ_w, TPR identity-окон, TPR partial@L, FPR public_test_windows при τ_w / при τ функций); в `summary.json` это `methods.<m>.tpr_windows["0.01"].{threshold, by_partial_L, by_transform.identity, fpr.public_test_windows, fpr_at_function_tau}` (ключ α обязателен). `⟨T2: пропуски M1 по причинам⟩` — строка «Пропуски членов по причинам» T2; `⟨T2: TPR M4, калибровка «1 запрос/функция»⟩` — строка «Все классы, калибровка «1 запрос/функция»». `⟨T3: Связи в τ⟩`, `⟨T3: τ мондриан⟩`, `⟨T3: FPR/TPR при τ мондриан⟩`, `⟨T3: p public_test⟩`, `⟨T3: МДЭ⟩` — одноимённые столбцы T3; `⟨T3: n функций в ячейке, min–max⟩`, `⟨T3: ячейки с «нет», α = 0,1 %⟩` — под-таблица T3 «По ячейкам мондриановской калибровки». `⟨T7: … по целевому языку⟩` — строки T7 с конкретным значением столбца «Целевой язык» (строка «все» — объединённая TPR по всем языкам, не среднее). `⟨T1: окон public_calib/public_test⟩`, `⟨T1: запросов <set>_windows⟩` — второй блок T1 «Запросы по наборам» и `summary.json: data_stats.functions.windows_by_split`; «Функций до дедупликации» = `data_stats.functions.splits[<split>].n_raw`, «Удалено близких к P» = `removed_near_dup + removed_sha_protected` (в T1 стенда этих столбцов нет — считать из `summary.json`).
2. `⟨Fn: описание⟩` — число из `results/summary.json` по тем же ключам, что читает `plots.fig_Fn` (файлов с точками стенд не сохраняет): F2 — `methods.<m>.tpr["0.01"].conformal.by_length_bin["0-32" … "256-100000"]` (бин «> 256» называется `256-100000`) и `by_partial_L["3" … "40"]`; F3 — `methods.<m>.auroc.hard_neg / public_test` (`value`, `ci`; напечатаны в легенде F3); F5 — `by_transform` гибридов против `max(by_transform winnowing, semantic)`; F6 — конфигурации фронта Парето по точкам `results/privacy.json` (A2 F1 при n = 10 000 × TPR M4).
3. `⟨summary: …⟩` — путь в `results/summary.json` (`fpr["0.01"].conformal.public_test.by_lang` / `by_transform` — максимум по подгруппам; `fpr["0.01"].conformal.hard_neg.test_above_alpha.p_value`); `⟨privacy: a1.prior_baseline.f1⟩` — из `results/privacy.json` (в T6 не печатается); `⟨index_stats: winnowing.meta n_common / (n_keys + n_common)⟩` — из `results/index_stats.json: winnowing.meta` основного индекса с окнами (`n_fps_total` включает отпечатки окон; варианты записаны как `winnowing@data/indexes_nofilter` и т. п.); `⟨T6: доля вхождений идентификаторов только P⟩` — примечание T6 («идентификаторов только protected … вхождений» = `privacy.json: a1.protected_coverage.protected_only_occurrence_fraction`); `⟨T6: случайный уровень …⟩` — скобка столбца «A1: полнота по редким идентификаторам (точность / случайный уровень)».
4. Голые `⟨Tn⟩` в ячейках таблиц 2–7 — вставить значения из `results/tables/Tn_*.md`. **Таблицы рукописи — проекции таблиц стенда**, а не копии: стенд выводит надмножество столбцов и строк: T1 — языки и бины длины (в рукописи — плейсхолдер в тексте); T2 — строки «калибровка «1 запрос/функция»», «оракульный порог», «Пропуски членов по причинам» (в тексте 6.1/6.3) и столбцы всех вариантов (в табл. 3 — только M1-lex); T3 — «Связи в τ», ДИ Клоппера–Пирсона, «1 запрос/функция» (τ и FPR), мондриан (τ, FPR, TPR, под-таблица по ячейкам), доменная калибровка, «FPR public_test vs α (z-тест; МДЭ)», блок «Сценарий IDE» (всё — в тексте 6.2/6.3); T4 — столбец «Описание», варианты `hybrid_own_small` / `semantic_own_small` (в рукописи строка «M3 собственная малая модель»; M4 с собственной моделью — только в репозитории); T5 — «Построение индекса», режим прогона, строки «— бенчмарк батч 1»; T6 — полностью, в рукописи только рис. 7 и текст; T7 — столбец «Целевой язык», строки по языкам, TPR/FPR всех методов. Соответствие столбцов — по заголовкам; при расхождении править `smcode/eval/tables.py`, а не рукопись. Дополнительные результаты, не вошедшие в рукопись (строки/столбцы выше, T6, F1–F4 с сериями вариантов), публикуются в репозитории стенда — об этом сказано в разд. 5.2 и 6.4 рукописи.
5. Метки `(Tn)` / `(Fn)` в конце подписей таблиц и рисунков — соответствие «номер в рукописи ↔ файл стенда»; перед подачей удалить.
6. Прочие: `⟨GPU⟩`, `⟨CPU⟩` (модель ускорителя и процессора, число потоков), `⟨GPU: размер микропакета B⟩` (фактический `--batch_size` шага 05: 128 на 80 ГБ, 32 × `--grad_accum 4` на 24 ГБ), `⟨URL репозитория⟩`, `⟨источник финансирования…⟩`, `⟨заполняет редакция⟩`.

Порядок заполнения: `⟨T1⟩` (N функций и окон protected — разд. 3.1, аннотация, введение; `⟨T5: записей M4⟩` = функции + окна — разд. 1, 8; число функций и запросов public_calib — разд. 6.3) → таблицы 3–7 → текстовые плейсхолдеры разд. 6 → разд. 1, 7, 8 и аннотации (повторяют числа разд. 6, сверять) → `⟨Fn⟩`. Шаблонные фразы разд. 6 написаны направление-нейтрально («разность … равна ⟨…⟩», «отношение FPR/α равно ⟨…⟩»); после заполнения проверить согласование падежей и знаков, но переписывать выводы не потребуется. Причинные интерпретации вынесены в разд. 7 и сформулированы как интерпретации. Проверка: `grep -c '⟨' paper/semantic_membership_ru.md` должно дать 0.

## 5. Состояние стенда относительно рукописи (сверено с кодом при второй правке)

Рукопись приведена к стенду `experiments/semantic_membership/` в его текущем виде (`README.md` стенда — runbook; `scripts/run_all.sh` — полный прогон; `scripts/smoke_test.sh` — синтетический прогон 01→02→03→04→07 (+ `winnowing_lexical`)→09, по которому сверены форматы таблиц).

**Сделано в стенде и отражено в рукописи:**

1. Кластерный бутстрэп для FPR (`metrics.fpr_block: ci_cluster`) — основной ДИ табл. 4; Клоппера–Пирсона — справочный столбец T3. Вывод о превышении α — односторонний кластерно-робастный z-тест (`test_above_alpha: p_value`) и МДЭ при мощности 80 % (`mde_80`) — разд. 6.3.

Псевдокод pre_call-ограждения (исключён из рукописи, разд. 4.7 описывает его словами):

```
procedure PRE_CALL(prompt):
    action ← NONE
    for q in extract_code_blocks(prompt):
        toks ← tokenize(q, detect_lang(q))
        r1 ← M1.query(abstract(toks, "full"))                 # поиск по словарю отпечатков
        e′ ← Q · f(strip_comments(q))                          # энкодер — доминирующая стоимость
        r4 ← M4.rerank(q, ANN.top_R(e′))                       # признаки (7), оценка (8); всегда вычисляется
        if r1.score > τ^(1)_{α/2} or r4.score > τ^(4)_{α/2}: return BLOCKED(explain(best_id))
        if r4.score > τ^(4)_{α′}: action ← GUARDRAIL_INTERVENED   # α′ > α: маскирование блока
    return action
```
