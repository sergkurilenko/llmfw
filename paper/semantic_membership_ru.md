**Аннотация.** Передача фрагментов исходного кода в запросах к большим языковым моделям стала одним из основных каналов утечки информации ограниченного доступа. Лексические отпечатки, применяемые в системах предотвращения утечек, разрушаются при переименовании идентификаторов и замене литералов, а отпечатки winnowing по абстрагированным токенам — при вставке мёртвого кода, частичном извлечении и перефразе. Задача формулируется как проверка членства: принадлежит ли фрагмент q из запроса защищённой кодовой базе P с точностью до класса преобразований T, порождаемого нарушителем. Предложен семантический слой LLM-файрвола — детектор на основе контрастивно дообученного энкодера кода и поиска ближайших соседей в индексе эмбеддингов — и гибридный детектор, переранжирующий кандидатов семантического поиска отпечатками winnowing с помощью обучаемого комбинатора. Порог назначается конформной калибровкой по негативам, что при обменяемости калибровочных и новых негативов даёт конечновыборочную границу уровня ложных срабатываний α без предположений о форме распределения оценок. Стенд моделирует защищённую базу открытыми репозиториями одной предметной области (сетевая безопасность, криптография), трудные негативы — другими репозиториями той же области; запросы формируются программными преобразованиями и преобразованиями большой языковой модели (перефраз, перевод на другой язык программирования). Результаты: вставка мёртвого кода снижает полноту winnowing с ⟨T2: TPR M1/identity⟩ до ⟨T2: TPR M1/insert_deadcode⟩, переименование идентификаторов — полноту лексических отпечатков с ⟨T2: TPR M0/identity⟩ до ⟨T2: TPR M0/rename_ids⟩, тогда как гибридный детектор даёт ⟨T2: TPR M4/insert_deadcode⟩ и ⟨T2: TPR M4/rename_ids⟩ при эмпирическом уровне ложных срабатываний ⟨T3: FPR public_test/M4, α = 1 %⟩ на публичном коде и ⟨T3: FPR hard_neg/M4, α = 1 %⟩ на трудных негативах (α = 1 %); задержка p95 гибридного детектора на CPU — ⟨T5: p95 M4, CPU, все потоки⟩ мс при индексе из ⟨T1: число функций protected⟩ функций; атака выравнивания по 1000 утёкшим парам восстанавливает ⟨T6: доля восстановленной утечки при n_ℓ = 1000⟩ % утечки незащищённого индекса. **Title:** Semantic Code Membership: Detecting Fragments of a Protected Codebase in Prompts to Large Language Models

**Authors:** [Authors, affiliation, ORCID]

**Abstract.** Source code pasted into prompts to large language models has become a major channel for leaking restricted information. Lexical fingerprints used by data-loss-prevention systems break once identifiers are renamed or literals replaced, while winnowing fingerprints over abstracted tokens break under dead-code insertion, partial extraction and paraphrase. We cast the problem as a membership test: does a fragment q from a prompt belong to a protected codebase P up to an adversary-generated class of transformations T? We propose a semantic layer for an LLM firewall — a detector built on a contrastively fine-tuned code encoder with nearest-neighbour search over an embedding index — and a hybrid detector that reranks semantic candidates with winnowing fingerprints through a trained combiner. The threshold is set by conformal calibration on negatives, which, under exchangeability of calibration and new negatives, yields a finite-sample bound on the false-positive rate α without assumptions on the score distribution. The testbed models the protected codebase with open repositories from one domain (network security, cryptography) and hard negatives with other repositories from the same domain; queries are produced by programmatic transformations and by LLM paraphrase and cross-language translation. Results: dead-code insertion lowers winnowing recall from ⟨T2: TPR M1/identity⟩ to ⟨T2: TPR M1/insert_deadcode⟩ and identifier renaming lowers lexical-fingerprint recall from ⟨T2: TPR M0/identity⟩ to ⟨T2: TPR M0/rename_ids⟩, whereas the hybrid detector reaches ⟨T2: TPR M4/insert_deadcode⟩ and ⟨T2: TPR M4/rename_ids⟩ at an empirical false-positive rate of ⟨T3: FPR public_test/M4, α = 1 %⟩ on public code and ⟨T3: FPR hard_neg/M4, α = 1 %⟩ on hard negatives (α = 1 %); the p95 CPU latency of the hybrid detector is ⟨T5: p95 M4, CPU, все потоки⟩ ms for an index of ⟨T1: число функций protected⟩ functions; an alignment attack with 1,000 leaked pairs recovers ⟨T6: доля восстановленной утечки при n_ℓ = 1000⟩ % of the leakage of the unprotected index. The testbed is released as open source.

**Keywords:** information security; large language models; source code leakage; LLM firewall; code fingerprinting (winnowing); code embeddings; code clone detection; conformal calibration; embedding inversion attack; protected codebase.

## 1. Введение

Запросы к большим языковым моделям (large language model, LLM) стали основным каналом неконтролируемого выноса исходного кода за периметр организации. По данным Netskope за 2026 г., исходный код составляет 42 % нарушений политик обращения с данными в генеративных ИИ-сервисах, число запросов на организацию выросло за год с 3 до 18 тыс. в месяц, объём данных — в 30 раз [1]; по оценке Cyberhaven, 39,7 % взаимодействий с ИИ-сервисами затрагивают чувствительные данные, из них 18,7 % — исходный код, а 32,3 % использования ChatGPT идёт через личные учётные записи [2]; по данным ГК «Солар», объём данных российских компаний в публичных нейросетях вырос за 2025 г. в 30 раз, и 8,5 % запросов содержат конфиденциальные сведения [3]. Регуляторный контекст ужесточается: проект требований ФСТЭК России по защите информации при использовании технологий искусственного интеллекта в государственных информационных системах запрещает передачу информации ограниченного доступа разработчику модели и требует доверенных технологий ИИ [4]; режим коммерческой тайны по Федеральному закону № 98-ФЗ предполагает меры по ограничению доступа к информации и контролю за её использованием [5]. Организации, допускающей использование LLM, необходимо средство, отвечающее на вопрос: содержит ли запрос фрагмент *защищённой кодовой базы*, а не просто «код»?

Классические средства предотвращения утечек (data loss prevention, DLP) решают иную задачу: обучаемые классификаторы определяют, что фрагмент является кодом [6], но не отличают собственный код организации от открытых библиотек; индексное сопоставление документов [7] и другие лексические отпечатки обнаруживают дословные копии, но разрушаются уже при переименовании идентификаторов и замене литералов; отпечатки winnowing по абстрагированным токенам [8], лежащие в основе MOSS, устойчивы к таким клонам, но разрушаются при вставке мёртвого кода (атака на MOSS автоматизирована [9]), частичном извлечении и перефразе. Каналы передачи — чат, ассистент в интегрированной среде разработки (integrated development environment, IDE), снимки экрана, журналы — порождают разные преобразования исходной функции, а IDE-канал ещё и жёстко ограничивает задержку.

Естественная точка принудительного исполнения политик — LLM-файрвол: прокси-шлюз между клиентскими приложениями и моделями (далее — шлюз), через который проходят все запросы и который предоставляет стандартный интерфейс ограждений — обработчики pre_call / during_call / post_call с действиями BLOCKED, NONE и GUARDRAIL_INTERVENED [10]. Детектор членства — pre_call-ограждение (guardrail), которое по запросу q возвращает оценку принадлежности (score; далее — оценка) к базе P и при превышении порога τ блокирует запрос, маскирует фрагмент или переадресует его доверенной локальной модели; в отличие от клиентских подходов (разд. 2) он не зависит от клиента и покрывает все каналы. Задача ставится как проверка членства (разд. 3): защищённая кодовая база P — множество функций и файловых окон закрытых репозиториев, индекс I(P) строится офлайн и развёртывается на шлюзе; запрос q либо получен из функции s ∈ P преобразованием t ∈ T (член), либо происходит из кода вне P (не-член); детектор D: q ↦ score принимает решение при score > τ. Для семантического слоя добавляется требование приватности индекса: эмбеддинги текста допускают почти дословную инверсию [11, 12], и индекс e = f(s) сам становится целью атаки инверсии эмбеддингов. Эту задачу мы называем *семантическим членством кода*; её отличие от обнаружения клонов и отслеживания происхождения кода разобрано в разд. 2, а ближайший аналог — гибрид векторного поиска с переранжированием отпечатками [13] — указывает развиваемое направление.

Цель работы — построить и экспериментально обосновать слой LLM-файрвола, обнаруживающий фрагменты защищённой кодовой базы P в запросах q с полнотой, устойчивой к классу преобразований T, при конечновыборочной границе уровня ложных срабатываний α и в бюджетах задержки шлюза. Задачи (исследовательские вопросы RQ1–RQ5): 1) оценить, насколько преобразования каждого класса T снижают полноту отпечатков winnowing и восстанавливает ли её семантический слой (RQ1); 2) измерить цену семантического слоя по ложным срабатываниям на публичном коде и трудных негативах той же предметной области и проверить, даёт ли конформная калибровка порога обещанную границу при сдвиге распределения (RQ2); 3) установить, превосходит ли гибрид «поиск по эмбеддингам → переранжирование отпечатками» каждую из компонент по полноте при фиксированном уровне ложных срабатываний и как эффект зависит от длины фрагмента (RQ3); 4) измерить стоимость слоя по задержке и памяти при индексе 10^5–10^6 функций на CPU и GPU относительно бюджетов чата и IDE (RQ4); 5) оценить, что утекает из индекса эмбеддингов при компрометации шлюза и какие защиты — ключевая ортогональная проекция, квантование, шум — сохраняют полноту при ограниченной утечке (RQ5).

Основные результаты (по задачам 1–5): 1) систематизирован класс T по каналам утечки и моделям нарушителя (разд. 3.4); вставка мёртвого кода снижает полноту winnowing с ⟨T2: TPR M1/identity⟩ до ⟨T2: TPR M1/insert_deadcode⟩, переименование — полноту лексических отпечатков с ⟨T2: TPR M0/identity⟩ до ⟨T2: TPR M0/rename_ids⟩, тогда как семантический слой на энкодере, не видевшем P, даёт ⟨T2: TPR M3/insert_deadcode⟩ и ⟨T2: TPR M3/rename_ids⟩ (разд. 6.1, 6.7); 2) протокол конформной калибровки порога τ_α с границей FPR ≤ α проверен при сдвиге: при α = 1 % FPR гибрида равен ⟨T3: FPR public_test/M4, α = 1 %⟩ на публичном коде и ⟨T3: FPR hard_neg/M4, α = 1 %⟩ на трудных негативах (разд. 6.3); 3) гибрид с обучаемым комбинатором даёт при FPR = 1 % полноту ⟨T4: TPR hybrid⟩ против ⟨T4: TPR лучшей компоненты⟩ у лучшей компоненты (разд. 6.2, 6.4); 4) задержка p95 гибрида на CPU равна ⟨T5: p95 M4, CPU, все потоки⟩ мс при N = ⟨T1: число функций protected⟩, бюджет чата исчерпывается при N ≈ ⟨F7: N, при котором p95 M4 = 50 мс⟩ (разд. 6.5); 5) построена модель угроз компрометации шлюза и измерены кривые «утечка — полнота» для проекции, квантования и шума под атаками инверсии и выравнивания (разд. 6.6).

Научная новизна: (1) впервые защита кода в запросах к LLM поставлена как членство q ∈_T P с точностью до порождаемого нарушителем класса T и моделью нарушителя Н1–Н4; (2) предложен гибридный детектор с обучаемым комбинатором (7)–(8) и конформным порогом; (3) впервые к детектору утечек кода применена конформная калибровка с конечновыборочной границей FPR, проверенная на трудных негативах; (4) впервые оценена приватность индекса эмбеддингов кода под атаками инверсии и выравнивания вместе с ценой защит по полноте. Практическая значимость: слой встраивается в LLM-файрвол как pre_call-ограждение [10] с двумя порогами, объяснимым вердиктом и управлением ключами, реализуя меры ограничения доступа по 98-ФЗ [5] и проекту требований ФСТЭК России [4]; открытый стенд позволяет повторить оценку на собственной базе.

## 2. Связанные работы

**DLP-системы.** Индексное сопоставление документов (Symantec DLP, Indexed Document Matching / Exact Data Matching) нормализует защищаемые документы, хэширует их необратимой функцией и ищет совпадающие хэши в сообщении [7]: индекс не раскрывает содержимого, но обнаруживает лишь дословные копии. Классификатор «Source Code» в Microsoft Purview распознаёт код на 23 языках [6], но отвечает на вопрос «является ли фрагмент кодом», а не «принадлежит ли он защищённой базе». Отслеживание происхождения на конечной точке (Cyberhaven Data Lineage) [14] требует агента на каждом устройстве и не видит переработанный код. Ни один механизм не ставит задачу как членство с точностью до класса T и не даёт гарантии уровня ложных срабатываний.

**Обнаружение клонов и энкодеры кода.** Классификация [15] выделяет клоны типа 1 (форматирование и комментарии), 2 (дополнительно переименованы идентификаторы и заменены литералы), 3 (добавлены, удалены или изменены операторы) и 4 (функционально эквивалентный, синтаксически иной код); класс T укладывается в неё (разд. 3.4), но клоны создаёт нарушитель, заинтересованный в обходе. Алгоритм winnowing [8] выбирает из хэшей k-грамм по одному минимальному в каждом окне ширины w и гарантирует общий отпечаток для любой общей подстроки длиной не менее w + k − 1 токенов; по абстрагированным токенам отпечатки устойчивы к клонам типов 1–2, но не 3: автоматическая вставка мёртвого кода (Mossad) снижает сходство по MOSS ниже порога при сохранении поведения [9]. SourcererCC [16] масштабирует обнаружение клонов типа 3 через перекрытие мультимножеств токенов, но его порог подбирается на размеченных парах, а не как граница FPR на открытом множестве не-членов; эталон BigCloneBench [17] отвечает постановке «клон / не клон», а не членству в закрытом множестве P. Нейросетевые представления кода — CodeBERT [18], GraphCodeBERT [19], UniXcoder, объединяющий абстрактное синтаксическое дерево (abstract syntax tree, AST) и комментарии в предобучении и лидирующий на обнаружении клонов и поиске кода без дообучения [20], CodeT5+ [21] — дают векторы, инвариантные к поверхностным преобразованиям, и служат основой семантического слоя, но поведение косинусной оценки на трудных негативах той же предметной области и её калибровка под фиксированный FPR в них не исследуются. LLM в роли детектора клонов [22] достигает F1-меры 0,943 на наборах класса CodeNet, но снижается на BigCloneBench, неприемлем для шлюза по задержке и требует передать проверяемый код внешней модели.

**Ближайший аналог.** Отслеживание происхождения (provenance) фрагментов, сгенерированных LLM [13]: энкодер SourceTracker (300 млн параметров) обучен на 10 млн фрагментов The Stack v2, а HybridSourceTracker переранжирует кандидатов векторного поиска алгоритмом winnowing; на корпусе из 100 тыс. фрагментов с адаптированными (переименованными) запросами гибрид сравнивается с winnowing при длине 30 токенов и превосходит его до 5,4 % начиная с 60 токенов при логарифмическом времени запроса. Отсюда заимствуется архитектура «поиск по эмбеддингам → переранжирование отпечатками». Отличия: в [13] база — открытый корпус, запросы порождены моделью, качество измеряется ранговой метрикой MRR; у нас база закрыта, запросы порождает нарушитель (T включает мёртвый код, частичное извлечение, перефраз и перевод), энкодер не должен видеть P, шлюзу нужно решение score > τ с конечновыборочной границей FPR, проверенной на трудных негативах, индекс I(P) нуждается в защите при компрометации, а переранжирование выполняет обучаемый комбинатор.

**Защита кода от провайдера LLM.** CodeCloak [23] обучает агента с подкреплением изменять запросы IDE-ассистента, снижая утечку примерно до 40 % при сохранении около 70 % сходства подсказок; CodeCipher [24] обучает обфускацию кода, сохраняющую полезность ответов LLM; для текста HaS [25] и PAPILLON [26] заменяют чувствительные сущности локальной моделью (PAPILLON сохраняет 85,5 % качества при 7,5 % утечки). От детектора членства их отличают: (i) размещение на клиенте — защита обходится другим клиентом или каналом и не покрывает нарушителя Н3 (разд. 3.3); (ii) снижение утечки любого кода без различения P ценой ~30 % сходства подсказок на каждом запросе, тогда как детектор действует только на фрагменты из P; (iii) отсутствие понятий защищённой базы, порога и гарантии FPR. Направления дополняют друг друга: детектор принимает решение, а маскирование или переадресация локальной модели реализуются средствами, подобными CodeCloak и PAPILLON. Результат [27] (сильные LLM сохраняют ~90 % Pass@1 на обфусцированном коде) имеет оборотную сторону: обфускация перед отправкой доступна и инсайдеру.

**Инверсия эмбеддингов и конформные гарантии.** Эмбеддинги текста раскрывают атрибуты и «мешок слов» входа [28]; vec2text восстанавливает дословно 92 % входов длиной 32 токена [11]; ALGEN проводит инверсию в режиме few-shot, выравнивая пространство неизвестного энкодера с известным по порядка тысячи пар [12]; генеративная инверсия на диффузионных моделях продолжает эту линию [29]. Атаки A1–A3 разд. 4.6 следуют соответственно [28], [12] и [11]. Защиты изучены для текстовых эмбеддингов (шум Махаланобиса, чувствительный к размерностям, несущим концепты [30]); для эмбеддингов кода вопрос не исследован, хотя именно здесь утечка редких идентификаторов — внутренних имён API, констант, секретов — составляет основной ущерб. Порог τ в детекторах безопасности традиционно назначается по ROC-кривой без конечновыборочных гарантий. Конформное предсказание [31, 32] даёт гарантию, свободную от предположений о форме распределения: при обменяемости (exchangeability) калибровочных и новых негативов порядковая статистика ранга ⌈(n + 1)(1 − α)⌉ по оценкам негативов обеспечивает Pr[score > τ_α] ≤ α (конформная калибровка); конформное управление риском [33] и Learn then Test [34] переносят гарантию на монотонные риски и совместный выбор порогов. В обнаружении утечек кода эти инструменты, по нашим сведениям, не применялись, а соблюдение гарантии при сдвиге на трудные негативы не проверялось.

## 3. Модель угроз и постановка задачи

### 3.1. Определения

Пусть P = {s_1, …, s_N} — защищённая кодовая база: множество фрагментов кода (функций, а для сценария IDE — также файловых окон) из закрытых репозиториев; рассматриваемый диапазон N ≈ 10^5–10^6 (в стенде — ⟨T1: число функций protected⟩ функций и ⟨T1: число окон protected⟩ окон, разд. 5.1). По P офлайн строится индекс I(P), развёртываемый на шлюзе; сама база на шлюз не передаётся. Запрос q — фрагмент кода, выделенный из промпта предшествующими слоями файрвола. Класс преобразований T — множество отображений t: s ↦ t(s) фрагмента кода в фрагмент кода на том же или ином языке, возможно рандомизированных. Фрагмент q называется членом P относительно T (q ∈_T P), если он получен из некоторой s ∈ P преобразованием t ∈ T; фрагмент, полученный из кода вне P, — не-членом. Метки определяются по происхождению: для коротких типовых фрагментов (три строки стандартной обработки ошибок) членство по происхождению неидентифицируемо — такой фрагмент буквально совпадает с окном некоторой функции из P, хотя взят извне; это ограничивает достижимую полноту на коротких фрагментах при фиксированном FPR (разд. 6.2) и мотивирует фильтр общности (разд. 4.2). В отличие от обнаружения клонов [15] одна сторона сравнения (P) фиксирована и закрыта, а решение принимается в реальном времени по одному запросу.

Детектор D: q ↦ score ∈ [0, 1] вычисляет оценку принадлежности; решение принимается правилом D_τ(q) = 1[D(q) > τ] со *строгим* неравенством: при массовых совпадениях оценок (у отпечаточных методов большинство негативов имеют оценку ровно 0) только строгое правило сохраняет границу разд. 4.5. Полнота (true positive rate, TPR) по преобразованию t: TPR_t(τ) = Pr[D(t(s)) > τ | s ∈ P]; уровень ложных срабатываний (false positive rate, FPR): FPR(τ) = Pr[D(q) > τ | q ∉_T P]; обе величины рассматриваются также по языку и длине фрагмента m_q в токенах.

### 3.2. Требования к детектору

(a) Полнота: высокая TPR_t при всех t ∈ T, включая преобразования, разрушающие k-граммы, и при коротких фрагментах; отчитывается по классам T, языкам и бинам длины (0–32, 32–64, 64–128, 128–256, более 256 токенов). (b) Ограниченный FPR с конечновыборочной гарантией: для α ∈ {10^−2, 10^−3} порог τ_α должен обеспечивать FPR ≤ α при конечной калибровочной выборке без предположений о форме распределения оценок — такую гарантию при обменяемости калибровочных и новых негативов даёт конформная калибровка (разд. 4.5); её соблюдение при сдвиге на код той же предметной области (трудные негативы) — отдельный предмет проверки. (c) Задержка: бюджет слоя на CPU — 50 мс для чата и 20 мс для IDE при индексе 10^5–10^6 записей; память индекса должна допускать размещение на одном узле шлюза. (d) Приватность индекса: I(P) содержит производную информацию о коде, составляющем коммерческую тайну [5], и размещается на шлюзе, который может быть скомпрометирован; требование эмпирическое — утечка под атаками A1–A3 (разд. 4.6) при n_ℓ утёкших парах «код — вектор» не должна превышать заданной доли утечки незащищённого индекса, а полнота (a) под защитами не должна снижаться более чем на заданную величину; измеренные утечки — нижние оценки (успех конкретной атаки), формальной верхней границы защиты не дают (разд. 7.2).

### 3.3. Нарушители

Принимается допущение Керкгоффса: нарушителю известны алгоритмы детектора (энкодер, k и w, схема калибровки), но неизвестны ключ K хэширования отпечатков и ключевая ортогональная матрица Q. Н1 — небрежный сотрудник: вставляет в чат функцию или её часть без умысла; преобразования — побочный результат копирования и адаптации (переформатирование, удаление комментариев, подстановка литералов, частичное извлечение); канал преобладает в статистике и инцидентах [1, 2, 35]. Н2 — IDE-ассистент: автоматически отправляет короткие окна контекста с границами, не совпадающими с границами функций, с высокой частотой; P дополняется файловыми окнами, T — частичным извлечением с L ∈ {3, 5, 10, 20, 40} строк. Н3 — инсайдер с умыслом: знает о детекторе и преобразует код, сохраняя его полезность для модели, но разрушая признаки сопоставления — согласованное переименование и замена литералов, вставка мёртвого кода (обходит winnowing без изменения поведения [9]), перестановка независимых операторов, их комбинация, перефраз и перевод на другой язык общедоступной LLM; ограничение — синтаксическая корректность и сохранение смысла; доступа к шлюзу и ключам нет. Н4 — компрометация шлюза: нарушитель получает копию I(P) — индекс отпечатков (ключевые хэши → идентификаторы) и индекс эмбеддингов (векторы e′_i = Q f(s_i), возможно квантованные и зашумлённые). Без ключа K хэши невоспроизводимы и не допускают перебора по словарю; даже с ключом индекс отпечатков позволяет лишь проверять кандидаты, но не перечислять P, поэтому риск сосредоточен в эмбеддингах. Два уровня знаний: (i) индекс без ключа и без пар «код — вектор» — модели инверсии обучаются на собственных данных и собственном экземпляре энкодера (n_ℓ = 0); (ii) индекс с n_ℓ ∈ {100, 1000, 10 000} утёкшими парами (s_j, e′_j), например из журналов отладки, по которым оценивается выравнивание Q̂ между пространствами. Вне рамок: пересказ алгоритма словами без кода; сессионное дробление (требует слоя с состоянием); проверка ответа модели на воспроизведение кода из P [13]; транспортное кодирование, снимаемое нормализацией.

## 4. Метод

Слой устроен как каскад: единая нормализация (разд. 4.1) питает детекторы по отпечаткам (разд. 4.2) и семантический энкодер (разд. 4.3), результаты которых объединяет гибридный детектор (разд. 4.4); порог задаётся конформной калибровкой (разд. 4.5); индекс эмбеддингов защищается проекцией, квантованием и шумом, стойкость которых проверяется тремя атаками (разд. 4.6); слой встраивается в шлюз как pre_call-ограждение (разд. 4.7). Все детекторы реализуют единый интерфейс: build(P) строит индекс, query(q) возвращает тройку (score, best_id, details). Гиперпараметры приведены по конфигурации стенда (`configs/default.yaml`).

### 4.1. Нормализация

Все методы работают с потоком токенов из синтаксического дерева tree-sitter [36] (идентификаторы, ключевые слова, операторы, пунктуация, числовые и строковые литералы, комментарии). Режимы абстракции: **full** — идентификаторы → `ID`, числа → `NUM`, строки → `STR`, комментарии удаляются (поток инвариантен к t_2–t_4 и t_8 по построению; winnowing, MinHash, дедупликация); **indexed** — идентификаторы → `ID_k` по порядку появления (словарь собственной малой модели); **lexical** — тексты токенов без комментариев (M0, словарь атаки A1). Функция strip_comments(q) возвращает код без комментариев — вход энкодера. Токены извлекаются и из поддеревьев ERROR, поэтому нормализация применима к неполным фрагментам и окнам IDE.

### 4.2. Детерминированные детекторы M0–M2

**M0 точный.** Лексический поток без комментариев разбивается на окна по 5 строк (фрагмент короче 5 строк — одно окно); индекс — множество 64-битных ключевых хэшей (BLAKE2b с ключом K) окон всех s ∈ P; оценка — доля окон запроса, найденных в индексе. Детектор моделирует индексное сопоставление документов в DLP [7].

**M1 winnowing.** Для потока full-токенов a_1, …, a_m образуются k-граммы g_i = (a_i, …, a_{i+k−1}) и их ключевые хэши

$$h_i = \mathrm{trunc}_{64}\big(\mathrm{HMAC\text{-}SHA256}(K, g_i)\big), \qquad (1)$$

где K — секретный ключ шлюза. По h_1, …, h_{m−k+1} скользит окно из w хэшей; в каждом выбирается минимум (при равенстве — самый правый), и множество выбранных хэшей образует отпечатки F(q). Гарантия winnowing [8]: общая подстрока длиной не менее δ = w + k − 1 токенов содержит не менее w подряд идущих k-грамм, т. е. хотя бы одно полное окно, минимум которого одинаков с обеих сторон. В стенде k = w = 25, δ = 49 токенов (5–8 строк). Индекс I_1(P) — отображение «хэш → массив идентификаторов записей»; оценка

$$D_1(q) = \frac{|F(q)\cap F(P)|}{|F(q)|}, \qquad F(P) = \bigcup_{s\in P} F(s); \qquad (2)$$

best_id — запись с наибольшим числом общих отпечатков, в details — длина наибольшей цепочки подряд идущих общих отпечатков. Ключевое хэширование (1) отвечает нарушителю Н4: без K хэш ни одной k-граммы невычислим, и утёкший индекс не позволяет ни проверить гипотезу о содержимом P, ни перечислить его по словарю типовых k-грамм.

**Фильтр общности.** Отпечатки, встречающиеся более чем в 50 функциях обучающего корпуса либо более чем в 5 % файлов P (и не менее чем в 3 файлах), исключаются из F(P) и F(q) (при пустом знаменателе в (2) оценка равна 0). Фильтр ослабляет гарантию: общая подстрока обнаруживается, только если хотя бы один её отпечаток не является общим. Но подстрока, все отпечатки которой общие, состоит из k-грамм, типичных для открытого кода (прологи импорта, шаблонная обработка ошибок, лицензионные заголовки), и одинаково совместима с происхождением из P и извне; её «необнаружение» — не потеря полноты, а снижение ложных срабатываний. Доля отпечатков P, удалённых фильтром, — ⟨index_stats: winnowing n_common_protected / n_fps_total⟩; влияние на TPR и FPR — разд. 6.4.

**M2 MinHash.** Шинглы из 5 full-токенов образуют множество; MinHash со 128 перестановками [37] (стандартная ошибка оценки коэффициента Жаккара J не превышает √(J(1 − J)/128) ≤ 0,044) и локально-чувствительное хэширование (locality-sensitive hashing, LSH) с порогом 0,3 [38] отбирают кандидатов, для которых считается точный коэффициент Жаккара; D_2(q) — его максимум. Мешок шинглов терпим к перестановке операторов и частично к мёртвому коду, подобно [16]; слабость — частичное извлечение.

### 4.3. Семантический энкодер M3

Базовая модель — UniXcoder-base [20] (12 слоёв, d = 768); альтернатива — codet5p-110m-embedding [21]. Эмбеддинг — усреднение по позициям (mean pooling) с L2-нормализацией:

$$u = \frac{1}{m}\sum_{j=1}^{m}\mathrm{Enc}\big(\mathrm{strip\_comments}(q)\big)_j, \qquad e = f(q) = u/\lVert u\rVert_2; \qquad (3)$$

вход — не более 512 подтокенов. Косинус равен скалярному произведению, и

$$D_3(q) = \max_{i} \langle e, e_i\rangle, \qquad e_i = f(s_i), \qquad (4)$$

то есть косинус с ближайшим соседом; число кандидатов R = 20 используется только гибридом. Индекс I_3(P) — матрица E ∈ ℝ^{N×d} в float16; поиск точный — FAISS IndexFlatIP [39] либо матричное произведение numpy; приближённый поиск (HNSW в составе FAISS) в стенде не измеряется.

**Контрастивное дообучение.** Модель без дообучения (zero-shot) — базовая линия. Дообучение выполняется на обучающем корпусе: якорь a_i — функция, позитив p_i = t(a_i) — её случайное преобразование, t равновероятно из программных преобразований T \ {identity} (partial — со случайным L); LLM-пара, если сгенерирована, берётся с вероятностью 0,5. Негативы для мини-пакета (batch) из B = 128 якорей — позитивы остальных якорей и общий пул H трудных негативов (по две функции того же файла на якорь, при нехватке — того же репозитория, затем случайные; |H| = 2B). Потеря — симметричный InfoNCE [40, 41] с температурой κ = 0,05:

$$\ell(a_i\!\to\!p_i) = -\log\frac{\exp(\langle e_{a_i}, e_{p_i}\rangle/\kappa)}{\sum_{j=1}^{B}\exp(\langle e_{a_i}, e_{p_j}\rangle/\kappa)+\sum_{h\in H}\exp(\langle e_{a_i}, e_h\rangle/\kappa)}, \qquad (5)$$

$$\mathcal{L} = \frac{1}{2B}\sum_{i=1}^{B}\big[\ell(a_i\!\to\!p_i) + \ell(p_i\!\to\!a_i)\big], \qquad (6)$$

где сумма по j включает j = i, а ℓ(p_i → a_i) определено симметрично с кандидатами {a_j} ∪ H. AdamW (weight decay 0,01), скорость обучения 2·10^−5 с линейным разогревом 5 % шагов и линейным убыванием, 2 эпохи, bf16; валидация по recall@1 на парах калибровочного корпуса. Негативы из того же файла делят с якорем словарь, API и стиль — то, что моделируют трудные негативы стенда. Негативы внутри пакета сами преобразованы, поэтому артефакты преобразований не становятся признаком класса; пул H не преобразуется, и в направлении a_i → [p; H] следы преобразования отличают позитив от H, но это не затрагивает направление p_i → a_i, совпадающее с режимом «преобразованный запрос — непреобразованный индекс». Код P в обучении не участвует (модель общая для всех заказчиков); абляции — дообучение с участием P и zero-shot (разд. 6.4). Вариант *собственная малая модель* — трансформер из 6 слоёв (размерность 384, 6 голов, BPE-словарь 32 000 над indexed- и lexical-потоками), обучаемый с нуля той же потерей при скорости обучения 3·10^−4; он не наследует весов и лицензий сторонних моделей, что важно для требований к доверенным технологиям ИИ [4].

### 4.4. Гибридный детектор M4

Косинус не отличает «ту же функцию с переименованными переменными» от «похожей функции того же назначения»; отпечатки точны, но хрупки. Гибрид использует поиск по эмбеддингам как генератор кандидатов, а отпечаточные признаки — как подтверждение, подобно [13], но с обучаемым комбинатором. Для каждого кандидата c из R = 20 ближайших соседей e_q вычисляется вектор признаков

$$x(q,c) = \big[\langle e_q, e_c\rangle,\ \mathrm{ovl}_w(q,c),\ \mathrm{lcr}(q,c)/|F(q)|,\ \log(1+m_q)\big], \qquad (7)$$

где ovl_w = |F(q) ∩ F(c)|/|F(q)| — доля отпечатков запроса у кандидата (попарно, без фильтра общности), lcr — длина наибольшей цепочки подряд идущих общих отпечатков (та же величина, что в details M1), m_q — длина запроса в токенах (логарифм сжимает диапазон длин и позволяет комбинатору по-разному доверять косинусу для коротких и длинных фрагментов). Оценка

$$D_4(q) = \max_{c}\ \mathrm{sigm}\big(\beta_0 + \beta^{\top}x(q,c)\big), \qquad (8)$$

sigm — логистическая функция. Комбинатор обучается только на обучающем корпусе: его репозитории делятся пополам по затравке; из первой половины строится индекс до 20 000 функций, члены — все программные преобразования 2000 якорей из индекса, не-члены — те же преобразования 2000 функций второй половины (других репозиториев, вне индекса), чтобы комбинатор видел распределение косинуса у настоящих не-членов; метка кандидата равна 1, только если запрос — член, а кандидат — его исходная функция; логистическая регрессия с балансировкой классов, C = 1. Абляция без обучения — правило двух порогов

$$D_4^{(2)}(q) = \max_{c}\ \max\{\rho(\langle e_q,e_c\rangle;\,\theta_{\cos}),\ \rho(\mathrm{ovl}_w(q,c);\,\theta_w)\}, \quad \rho(x;\theta)=\begin{cases}x/(2\theta), & x<\theta,\\ 1/2+(x-\theta)/(2(1-\theta)), & x\ge\theta,\end{cases} \qquad (9)$$

с θ_cos = 0,8, θ_w = 0,2: ρ равно 1/2 в точке порога, так что «оценка ≥ 1/2» равносильно «cos ≥ θ_cos или ovl_w ≥ θ_w»; единственный калибруемый порог — τ_α поверх этой оценки.

### 4.5. Конформная калибровка порога

Для каждого детектора и α ∈ {10^−2, 10^−3} порог вычисляется методом split conformal для нулевого класса [31, 32]. Пусть z_1, …, z_n — оценки негативов калибровочного корпуса с той же матрицей преобразований, что у членов, z_(1) ≤ … ≤ z_(n) — порядковые статистики, j = ⌈(n + 1)(1 − α)⌉. Тогда

$$\tau_\alpha = z_{(j)}, \qquad (10)$$

где при j > n полагается τ_α = +∞; содержательный порог существует при n ≥ ⌈1/α⌉ − 1 (999 для α = 10^−3).

*Утверждение.* Если оценка нового не-члена z_new обменяема с z_1, …, z_n, то Pr[z_new > τ_α] ≤ α при любой структуре совпадений; при непрерывном распределении также Pr[z_new > τ_α] ≥ α − 1/(n + 1). Доказательство: в силу обменяемости ранг ρ величины z_new среди n + 1 оценок (при совпадениях — по случайному порядку) равномерен на {1, …, n + 1}; если z_new > z_(j), то не менее j калибровочных оценок строго меньше z_new и ρ ≥ j + 1, откуда Pr ≤ (n + 1 − j)/(n + 1) ≤ α; без совпадений события {z_new > z_(j)} и {ρ ≥ j + 1} равны, что даёт нижнюю оценку. Для нестрогого правила «≥ τ» граница не выполняется: если большинство негативов имеют оценку 0 (M0, M1), τ_α может равняться 0, и правило «≥ 0» срабатывало бы на всех негативах.

Границы применимости. (i) Гарантия безусловная (маргинальная): внутри подгруппы (язык, преобразование, длина) FPR может превышать α, поэтому FPR отчитывается и по подгруппам. (ii) Обменяемые единицы — функции-источники, а не запросы: при матрице «функция × преобразование» оценки кластеризованы по 13 на функцию, и объединённая калибровка по n запросам — приближение, проверяемое эмпирически на тестовом корпусе. Строгий вариант — мондриановская калибровка по ячейкам t (преобразование, для partial — также L): в ячейке ровно один запрос на функцию, (z_1, …, z_m, z_new) обменяемы при m функциях и Pr[z_new > τ_{α,t} | t] ≤ α доказуемо, а порог развёртывания max_t τ_{α,t} даёт FPR ≤ α при любой смеси преобразований ценой консервативности; требование m ≥ ⌈1/α⌉ − 1 относится к числу функций на ячейку (в стенде — ⟨T1: число функций public_calib⟩). (iii) Сдвиг распределения: трудные негативы не обменяемы с калибровочным корпусом, их оценки стохастически больше, и FPR на них может превышать α — предмет RQ2. (iv) Доменная калибровка: половина репозиториев трудных негативов (по затравке) добавляется к калибровочным негативам, остальные остаются в тесте; порог считается по объединению, поэтому граница относится к смеси «публичный корпус + доменные репозитории», а обменяемость на уровне репозиториев при 6 калибровочных и 6 тестовых — сильное допущение; результат проверяется эмпирически. Для сравнения приводится идеальный (оракульный) порог по тестовому корпусу; под каждой защитой индекса (разд. 4.6) порог калибруется заново.

### 4.6. Приватность индекса эмбеддингов

**Ключевая ортогональная проекция.** Из ключа порождается гауссова матрица G ∈ ℝ^{d×d}; QR-разложение с коррекцией знаков столбцов (diag R > 0, Q равномерна на ортогональной группе) даёт Q; в индексе хранятся e′_i = Q e_i, запрос проецируется той же матрицей. Поскольку

$$\langle e'_q, e'_i\rangle = e_q^{\top}Q^{\top}Qe_i = \langle e_q, e_i\rangle, \qquad (11)$$

косинусы, кандидаты, оценки (4), (8) и пороги не меняются — защита бесплатна по полноте. Модели инверсии, обученные на собственном экземпляре энкодера, — функции координат, и при неизвестном повороте базиса их вход не соответствует обучающему распределению. Проекция, однако, не скрывает геометрию (попарные расстояния, структура кластеров и дубликатов P сохраняются), а нарушитель, способный согласовать распределения — сопоставить собственные базисы ковариаций Σ_pub ≈ Σ и QΣQᵀ и уточнить поворот итеративным Прокрустом по взаимным ближайшим соседям, — может оценить Q и без утёкших пар. Проекция не является криптографической защитой; при n_ℓ = 0 стенд оценивает лишь прямое применение A1 к спроецированным векторам, неконтролируемое выравнивание не реализовано (разд. 7.2).

**Квантование и шум.** Квантование до int8, int4 и бинарного (знакового) представления сокращает память примерно в 2, 4 и 16 раз относительно float16 и уничтожает младшие разряды координат; при поиске используются деквантованные векторы. Шум добавляется только к хранимым векторам: ẽ_i = (Q e_i + ξ_i)/‖Q e_i + ξ_i‖, ξ_i ~ N(0, (σ²/d) I_d), σ ∈ {0,05; 0,1; 0,2} — отношение нормы шума к норме вектора. Для единичного запроса ⟨e′_q, ẽ_i⟩ ≈ (⟨e_q, e_i⟩ + η)/√(1 + σ²), η ~ N(0, σ²/d): множитель 1/√(1 + σ²) (0,999; 0,995; 0,981) одинаков для всех пар и поглощается калибровкой, а возмущение оценки имеет стандартное отклонение σ/√d (0,002; 0,004; 0,007 при d = 768); именно оно, а не косинус между чистым и зашумлённым вектором, определяет потерю полноты. Схемы шума, адаптивные к размерностям [30], совместимы с конструкцией, но не исследуются.

**Атаки.** A1 — инверсия «мешок токенов»: по вектору предсказывается наличие каждого из V = 20 000 идентификаторов словаря обучающего корпуса (частые по документной частоте плюс квота редких, 2 ≤ df ≤ 3); модель — многослойный перцептрон или гребневая регрессия на парах (f(a), bow(a)) с порогом на каждый токен, максимизирующим его F1-меру на вневыборочных оценках; на P измеряются micro-F1 по идентификаторам и доля восстановленных редких идентификаторов (df ≤ 3), несущих предметные имена [28]; базовая линия — априорное предсказание одного набора токенов для всех функций. A1 на незащищённом индексе — опорный уровень для данной атаки, а не верхняя граница утечки. A2 — выравнивание по n_ℓ ∈ {0, 100, 1000, 10 000} утёкшим парам (s_j, e′_j) [12]: нарушитель вычисляет e_j = f(s_j) и решает задачу ортогонального Прокруста

$$\hat Q = \arg\min_{\Omega^{\top}\Omega = I}\lVert E' - E\Omega^{\top}\rVert_F, \qquad \hat Q^{\top} = UV^{\top}, \quad U\Sigma V^{\top} = \mathrm{SVD}(E^{\top}E'), \qquad (12)$$

после чего применяет A1 к Q̂ᵀe′ (при n_ℓ = 0 полагается Q̂ = I). Без шума и квантования n_ℓ ≥ d линейно независимых пар восстанавливают Q точно, при n_ℓ < d оценка корректна лишь на подпространстве утёкших пар. A3 — генеративная инверсия: декодер-трансформер (6 слоёв, размерность 384), обусловленный на e′ как на префикс, обучается восстанавливать лексические токены функции; метрики — BLEU-4 и доля восстановленных идентификаторов; одношаговая схема без итеративной коррекции [11] даёт нижнюю оценку генеративной утечки. Полезность конфигурации — TPR при FPR = 1 % детекторов M3 и M4 при калибровке под той же защитой.

### 4.7. Схема развёртывания

Слой встраивается в прокси как pre_call-ограждение (интерфейс LiteLLM [10]) с действиями BLOCKED, GUARDRAIL_INTERVENED (маскирование блока кода по аналогии с заменой чувствительных сущностей [25, 26]) и NONE. Для каждого блока кода вычисляются оценки M1 и M4 (энкодер → R = 20 кандидатов → признаки (7) → оценка (8)); обе ступени выполняются всегда, решение принимается по обеим (постоянное время ответа). Решение каскада — дизъюнкция «D_1 > τ^{(1)} или D_4 > τ^{(4)}», поэтому гарантия (10) для порогов на уровнях α_1 и α_4 даёт по границе объединения FPR ≤ α_1 + α_4; для заявленного α ступени калибруются на α/2 каждая либо единой процедурой (10) калибруется оценка каскада max(D_1, D_4); совместный выбор порогов возможен методом Learn then Test [34]. Третий порог на уровне α′ > α задаёт маскирование вместо блокировки. Объяснение вердикта строится по best_id формата `repo/path:start-end` и details (число общих отпечатков, длина цепочки, косинус): полная форма направляется в журнал центра мониторинга безопасности (SOC) и администратору безопасности, пользователю — сокращённая, поскольку детализированная обратная связь служила бы нарушителю Н3 оракулом для итеративного обхода; частота околопороговых запросов ограничивается. Ключ K и затравка Q хранятся отдельно от индекса; ротация K требует переиндексации P; после существенного роста индекса калибровка пересчитывается по (10) без нового сбора данных, поскольку максимум косинуса по большему индексу стохастически больше.

### 5.1. Данные

Закрытая кодовая база организации в публикуемом эксперименте недоступна, поэтому её роль выполняет набор открытых репозиториев одной предметной области — сетевая безопасность, VPN, криптография, обнаружение вторжений (OpenVPN, strongSwan, libsodium, Suricata, Zeek, scapy, pyca/cryptography и др.; список — в `configs/repos.yaml`). Пул из 24 репозиториев-кандидатов на шести языках (Python, C, C++, Go, Java, JavaScript) делится по затравке: 12 репозиториев образуют защищённую базу P (сплит protected), остальные 12 — *трудные негативы* (сплит hard_neg): код той же области, с теми же библиотеками, идиомами и соглашениями об именовании, но не входящий в P; на нём проверяется, не принимает ли детектор тематическое сходство за членство и выполняется ли граница FPR при сдвиге (RQ2). *Публичный корпус* — репозитории других областей (веб-фреймворки, обработка данных, компиляторы, игры, утилиты): 373 репозитория в списке конфигурации; содержащие ключевые слова домена P в имени, описании или темах, недоступные и объёмом более 300 МБ исключаются, фактическое число — ⟨T1: репозиториев public_*⟩ (табл. 2). ### 5.2. Наборы запросов и методы

Для P (члены, label = 1) и для каждого набора негативов — калибровочного, тестового и трудных негативов (label = 0) — запросы строятся одинаково: из сплита отбирается до 5000 функций со стратификацией по языку и бину длины, к каждой применяется каждое программное преобразование t_0–t_8, а partial — для каждого L ∈ {3, 5, 10, 20, 40}; итого до 13 запросов на функцию. Сравниваемые методы описаны в разд. 4 с параметрами стенда: M0 точный (окна по 5 строк); M1 winnowing (k = w = 25, фильтр общности); M2 MinHash (128 перестановок, шинглы из 5 токенов, LSH с порогом 0,3); M3 семантический — UniXcoder-base без дообучения и после дообучения на обучающем корпусе, точный поиск; M4 гибридный — R = 20 кандидатов M3, признаки (7), логистический комбинатор; абляции — правило двух порогов (9), исключение каждого признака, M1 без фильтра общности, M3 с адаптацией на P и собственная малая модель. P не участвует ни в обучении энкодера, ни в обучении комбинатора.

### 5.3. Метрики и воспроизводимость

Основная метрика — TPR при фиксированном FPR = α, α ∈ {10^−2, 10^−3}, по двум порогам: конформному τ_α по калибровочному корпусу (эксплуатационный режим: порог назначается до тестовых данных) и идеальному (оракульному) — минимальному порогу, при котором доля тестовых негативов с оценкой выше него не превышает α (верхняя граница достижимого). TPR приводится по преобразованиям, языкам и бинам длины, для partial — по L, для набора окон — отдельно; дополнительно — площадь под ROC-кривой (AUROC) для пар «члены — тестовый корпус» и «члены — трудные негативы». Соблюдение гарантии проверяется эмпирическим FPR при τ_α на тестовом корпусе (та же популяция) и трудных негативах (сдвиг), при доменной калибровке — на тестовой половине репозиториев. Доверительные интервалы (ДИ, 95 %) для TPR, FPR и AUROC — бутстрэп с 1000 повторениями и кластеризацией по исходной функции (13 запросов одной функции коррелированы, бутстрэп по запросам занизил бы дисперсию); для FPR дополнительно приводится интервал Клоппера–Пирсона [42], точный лишь при одном запросе на функцию и потому заниженный для объединённого набора. Задержка — p50 и p95: инференс энкодера — по 200 повторам на выборке запросов в одном потоке и во всех потоках CPU стенда при пакете 1 и на GPU при пакетах 1 и 32; полный метод — по 200 повторам одиночных запросов на выборке из N запросов. Метрики приватности — по разд. 4.6. Единый показатель F1 как итоговая метрика не используется; полные матрицы ошибок сохраняются в `results/summary.json`.

Дообучение, эмбеддинги, LLM-преобразования и атака A3 выполняются на ⟨GPU⟩; задержка на CPU измеряется на ⟨CPU⟩ с явным ограничением числа потоков. Гиперпараметры перечислены в `configs/default.yaml`, списки репозиториев — в `configs/repos.yaml`; единая затравка 20261003 определяет выбор репозиториев, отбор функций, параметры преобразований и инициализацию обучения. Ключ HMAC читается из переменной окружения и в репозитории не хранится; на метрики он не влияет. Конвейер скриптов 00–09 (клонирование, извлечение, дедупликация, запросы, индексы, дообучение, эмбеддинги, оценка, приватность, отчёт) идемпотентен; таблицы и рисунки генерируются из `results/`; CPU-часть покрыта модульными тестами на синтетических данных (без сети и без torch). Код опубликован: ⟨URL репозитория⟩.

## 7. Обсуждение и ограничения

### 7.1. Следствия для развёртывания

В каскаде разд. 4.7 детерминированный слой M1 остаётся первой ступенью: он стоит миллисекунды (⟨T5: p50 M1, CPU-1⟩ мс), не требует энкодера и обнаруживает фрагменты классов t_0–t_4 и t_8 с полнотой ⟨T2: TPR M1/identity⟩, закрывая большую часть канала Н1. Семантический слой окупается там, где отпечатки разрушены: на вставке мёртвого кода, частичном извлечении и перефразе полнота M1 равна ⟨T2: TPR M1/insert_deadcode⟩, ⟨T2: TPR M1/partial⟩ и ⟨T7: TPR M1/paraphrase⟩, гибрида — ⟨T2: TPR M4/insert_deadcode⟩, ⟨T2: TPR M4/partial⟩ и ⟨T7: TPR M4/paraphrase⟩. Цена — инференс энкодера: p95 гибрида на CPU при полном индексе составляет ⟨T5: p95 M4, CPU, все потоки⟩ мс при бюджете 50 мс для чата и 20 мс для IDE, бюджет чата исчерпывается при N ≈ ⟨F7: N, при котором p95 M4 = 50 мс⟩; для IDE семантическая ступень на CPU допустима, если ⟨T5: p95 M4, CPU, все потоки⟩ ≤ 20 мс, иначе переносится на GPU либо применяется только к окнам длиннее ⟨F2: длина смены знака, токенов⟩ токенов.

Два порога имеют операционный смысл. Если бы каждый из ~18 тыс. запросов в месяц на организацию [1] содержал один фрагмент кода вне P, уровень α = 10^−2 давал бы не более ~180 ложных вмешательств в месяц, α = 10^−3 — не более ~18; доля запросов с кодом (18,7 % по [2]) пропорционально снижает эти числа. Ложная блокировка дороже ложного маскирования, поэтому блокировка назначается на уровне 10^−3 с полнотой ⟨T2: TPR M4, α = 0,1 %⟩, маскирование — на уровне 10^−2 с полнотой ⟨T2: TPR M4, α = 1 %⟩; при двух ступенях уровни делятся между ними (разд. 4.7). Объяснимость опирается на best_id и признаки (7): доля общих отпечатков и длина их цепочки делают сверку администратором безопасности проверяемой, тогда как вердикт M3 подкреплён лишь косинусом.

Граница FPR держится на обменяемости. На тестовом корпусе FPR ⟨T3: FPR public_test/M4, α = 1 %⟩ проверяет саму процедуру; на трудных негативах он равен ⟨T3: FPR hard_neg/M4, α = 1 %⟩ [ДИ ⟨T3: ДИ FPR hard_neg/M4⟩], и отклонение от α — мера сдвига; доменная калибровка даёт ⟨T3: FPR hard_neg_test M4 при доменной калибровке⟩ на тестовых репозиториях ценой полноты ⟨T3: TPR M4 при доменной калибровке⟩, причём граница относится к смеси «публичный корпус + доменные репозитории». Отсюда три правила: калибровочные негативы берутся из предметной области организации (открытые зависимости, ранее опубликованный код); доля срабатываний отслеживается во времени, и её выход за α с учётом ДИ — сигнал к перекалибровке; при неоднородности по языку, длине или классу применяются мондриановские пороги по группам [31] (разд. 4.5), что требует не менее ⌈1/α⌉ − 1 функций-источников на группу.

### 7.2. Угрозы валидности и ограничения

(1) Закрытую базу моделируют открытые репозитории: корпоративный код содержит больше уникальных внутренних имён (облегчает членство и увеличивает ущерб от A1), а единый стиль организации делает «свои» трудные негативы ближе к P; направление суммарного смещения неизвестно. (2) Энкодер мог видеть P при предобучении: UniXcoder обучен на CodeSearchNet из открытых репозиториев [20], и часть репозиториев-кандидатов, вероятно, входила в этот корпус; дообучение исключает P, предобучение — нет. Оценкой, свободной от этой угрозы, служит собственная малая модель: её полнота ⟨T4: TPR own_small_model⟩ против ⟨T4: TPR M3 (UniXcoder)⟩ ограничивает сверху совместный эффект масштаба предобучения и возможного запоминания; C и C++, отсутствующие в CodeSearchNet, для энкодера частично вне распределения (табл. 3). (3) Преобразования t_1–t_8 сохраняют поведение по построению, t_9 проверяются лишь синтаксически; класс T не является адаптивной атакой — нарушитель Н3, наблюдающий вердикты, мог бы оптимизировать преобразование итеративно, как Mossad против MOSS [9], и полнота на t_3–t_8 для него — верхняя оценка. (4) Охвачены шесть языков с неравномерным распределением P (табл. 2); другие языки требуют грамматик tree-sitter и списков ключевых слов, но не изменений метода. (5) Реальных запросов сотрудников нет: запросы синтетические, из одного фрагмента, тогда как реальные промпты смешивают код с текстом и трассировками, а ошибки извлечения блоков кода переносятся на детектор; эксплуатационная калибровка должна выполняться на проверенных аудитом негативах из трафика организации. (6) Интервалы для FPR на трудных негативах опираются на 12 репозиториев (6 при доменной калибровке) — малое число независимых единиц.

Приватность индекса. Нарушитель, получивший вместе с индексом ключ (затравку Q), снимает проекцию и возвращается к утечке ⟨T6: A1 F1, без защиты⟩; остаточную защиту дают лишь квантование и шум — аргумент за хранение ключа отдельно от индекса. При n_ℓ ≥ d = 768 парах без шума Q восстанавливается точно (12): журналы отладки с векторами обнуляют проекцию. Проекция сохраняет геометрию (число векторов, структура кластеров и дубликатов P видны без ключа), а неконтролируемое выравнивание (разд. 4.6) не оценивается, поэтому утечка при n_ℓ = 0 — нижняя оценка. Шум σ не является дифференциально-приватным механизмом и формальной границы не даёт; все измеренные утечки — успех конкретных атак, т. е. нижние оценки. Отдельный канал — сам вердикт: детектор является оракулом членства, и пользователь, наблюдающий блокировку, узнаёт, что фрагмент принадлежит P; полный best_id раскрыл бы и структуру репозиториев, поэтому пользователю выдаётся сокращённая форма, а частота околопороговых запросов ограничивается; устранить оракул, не отказавшись от детектора, нельзя.

Установлено, какие преобразования разрушают отпечатки: лексические отпечатки M0 теряют полноту при переименовании идентификаторов (⟨T2: TPR M0/identity⟩ → ⟨T2: TPR M0/rename_ids⟩), отпечатки winnowing M1 — при вставке мёртвого кода, частичном извлечении и перефразе (⟨T2: TPR M1/identity⟩ → ⟨T2: TPR M1/insert_deadcode⟩, ⟨T2: TPR M1/partial⟩, ⟨T7: TPR M1/paraphrase⟩); семантический слой на энкодере, не видевшем P, даёт на этих преобразованиях ⟨T2: TPR M3/insert_deadcode⟩, ⟨T2: TPR M3/partial⟩ и ⟨T7: TPR M3/paraphrase⟩, на переводе — ⟨T7: TPR M3/translate⟩. 2. Показано, что конформный порог при строгом правиле решения обеспечивает FPR ⟨T3: FPR public_test/M4, α = 1 %⟩ при α = 1 % на негативах той же популяции и ⟨T3: FPR hard_neg/M4, α = 1 %⟩ при сдвиге на трудные негативы; доменная калибровка возвращает FPR к ⟨T3: FPR hard_neg_test M4 при доменной калибровке⟩ ценой полноты ⟨T3: TPR M4 при доменной калибровке⟩. 3. Гибрид с обучаемым комбинатором отличается от лучшей компоненты на ⟨T4: ΔTPR hybrid − лучшая компонента⟩ п.п. полноты при FPR = 1 % с зависимостью от длины фрагмента (⟨F2: ΔTPR M4 − лучшая компонента по L⟩), а его FPR на трудных негативах составляет ⟨T4: FPR hard_neg M4⟩ против ⟨T4: FPR hard_neg M3⟩ у семантического слоя. 4. Задержка p95 гибрида на CPU равна ⟨T5: p95 M4, CPU, все потоки⟩ мс при N = ⟨T1: число функций protected⟩ и достигает бюджета чата при N ≈ ⟨F7: N, при котором p95 M4 = 50 мс⟩; память индекса эмбеддингов — ⟨T5: память M3 float16⟩ МБ. 5. Ключевая проекция бесплатна по полноте, но её обход по n_ℓ = 1000 утёкшим парам восстанавливает ⟨T6: доля восстановленной утечки при n_ℓ = 1000⟩ % утечки незащищённого индекса; на фронте «утечка — полнота» лежат конфигурации ⟨F6: конфигурации фронта Парето⟩. Слой встраивается в LLM-файрвол как pre_call-ограждение [10] с двумя порогами, объяснимым вердиктом и управлением ключами и реализует меры ограничения доступа по 98-ФЗ [5] и проекту требований ФСТЭК России [4]; стенд опубликован.
